# 缩略图资源回归设计

目标：对已定义 TC07-02～09 的资源与格式规则增加可执行证据。用户场景是恶意或损坏图片、对象存储元数据不可信以及同时生成缩略图时服务不应耗尽资源。

边界：仅测试 ThumbnailRenderer 真实实现，StorageService 和 S3Client 使用替身，不访问实际对象存储或数据库。输入由内存生成的 PNG/JPEG、伪装文本、可控制阻塞与异常的 InputStream 构成。阈值通过 ReflectionTestUtils 设置后执行 initialize，与配置注入后的逻辑一致。

规则：HEAD 声明长度高于阈值应阻止读取；声明长度未超但实际流超限应在有限缓冲内停止。图片实际格式须受白名单检查，输出可解码且尺寸正确；并发许可用闩锁确定性占用，不靠 sleep。异常后关闭流并释放许可，下一次合法请求可成功。

风险：此层不能覆盖 API 鉴权、分享计数、历史版本的对象键、浏览器降级及真实 ImageIO 超大头攻击。仅按对应单个用例的覆盖范围标 PASS 或 PARTIAL，不把服务层通过算成全部 136 用例通过。无 API、数据模型、数据库修改，也不改变前端 ID 字符串契约。

新增发现：服务端 Jackson 将 Long 游标输出为字符串，但桌面 fetchDelta 的 String(payload.cursor) 会接受已舍入的 JS 数字。修复为只接受规范十进制字符串游标，拒绝数字、负数、前导零和非法格式；这是既有同步 v2 契约的收紧，不改变合法响应。用真实当前源码的边界测试覆盖大游标和非法响应，完整重启分页链仍另行验证。

后续补测：TC05-01 使用 st-share 的 H2 真 Mapper、无测试外层事务、五个独立线程和受控存储流闩锁，让所有请求先通过前置校验再竞争同一条下载许可。流输出由每请求独立的 MockHttpServletResponse 捕获；验证只有一个非空响应和 count=1。此证据只能证明当前 Service+H2 行为，真实 MySQL 与双实例仍是单独门禁。
