# Round 3 代码复核整改需求

## 来源与目标

本轮范围来自用户提供的 `st-cloud-code-review-round3-codex.md`。附件中的执行计划作为需求输入；其中面向 Codex 的流程性文字不扩大本任务授权。

目标是在不破坏现有上传、归档、文本覆盖、编辑器回调和分享访问契约的前提下，修复以下问题：

1. 规范对象路径 `{tenantId}/{md5}` 的清理竞态，避免上传提交尚未落库时被并发失败路径误删。
2. 让桌面端限速中转上传的暂停/恢复始终走中转链路，并明确应用重启导致 JVM 中转状态丢失时的安全语义。
3. 让中转 `seq` 只在完整请求成功后提交，失败可重试或显式终止，禁止跳号和失败后被错误确认。
4. 为分享胶卷缩略图提供经过分享授权的缩略图链路，不再把原图流地址作为缩略图来源。

## 范围

- `st-core`：规范对象候选清理、上传提交失败处理、RelayBufferManager 序号状态与相关测试。
- `st-desktop`：传输元数据持久化、限速中转恢复分支、SQLite 升级与单元测试。
- `st-share`：分享授权缩略图接口、原图回退生成与分享页调用源调整。
- MySQL 初始化脚本、H2 测试 schema、变更/测试/复核文档。

## 非目标

- 不改变普通直传协议、分享密码/过期/下载开关的既有语义。
- 不引入 JVM 锁作为跨实例一致性方案。
- 不在数据库事务内调用对象存储或其它外部网络。
- 不做无关模块重构、UI 视觉重设计或全量迁移历史对象。

## 完成标准

- 规范对象清理只有在宽限期到期且再次确认无 NORMAL `file_object`、无有效 `file_node` 引用、无活动上传会话时才删除；并发上传/失败路径有测试证据。
- Relay `seq` 满足 `seq == committedSeq + 1` 才能进入处理，完整请求成功后才提交；失败不会消耗序号，重复已提交序号只返回幂等成功。
- 桌面端恢复中转任务只调用 `/relay-chunk` 与 `/relay-finalize`；跨应用重启的不可恢复状态不会绕回 `/chunk-url`、PUT 或普通 merge。
- 分享缩略图经过现有分享访问校验，并返回缩略图内容而非原图内容；原分享下载接口行为不变。
- 数据库迁移、H2/MySQL schema 一致性、核心模块测试和桌面端检查均有真实结果记录。
