# 安全审查报告

## 结论

安全审查通过，无新增 P0/P1 安全问题。审查重点覆盖对象误删、租户隔离、relay 状态污染和分享缩略图越权。

## 检查结果

### 规范对象

- 候选以 `tenant_id + storage_path` 唯一标识，查询和引用检查带租户条件。
- 失败路径不再直接删除规范对象；删除前同时检查 `NORMAL file_object`、有效 `file_node` 引用和活动 `upload_session`。
- deleting 状态禁止新的同路径登记；安全检查失败或存储删除失败会释放回 pending。
- 数据库变更与对象存储调用分离，避免事务回滚后留下不可逆物理删除。

### Relay

- seq 严格连续，重复只确认已提交序号，跳号和并发请求不会推进状态。
- 请求体、临时文件写入和远端 part 上传全部成功后才提交 seq。
- 远端 part 失败时显式中止会话，避免不确定 part 被重试拼接。
- 桌面端重启后不调用普通 chunk URL、PUT 或 merge，不会把 relay 任务降级成另一套协议。

### 分享缩略图

- endpoint 继续执行分享码、密码/验证码、过期、下载开关和节点范围校验。
- 只允许分享范围内的图片节点，输出服务端生成/缓存的 JPEG 缩略图，不直接把原图作为胶卷资源返回。
- 缩略图请求不递增原文件下载计数，避免 UI 资源请求伪造下载行为。

## 残留风险与运维要求

- relay 依赖服务端 JVM 会话；重启后客户端必须重新上传，服务端依靠既有超时 abort 清理旧会话和 multipart。
- 首次缩略图生成会发生一次原图读取和预览桶写入，调用位于事务外；生产部署仍应关注大图请求延迟和缓存命中率。
- 新迁移已在本地开发/测试 MySQL 执行并完成两次 schema 对比；生产迁移需在发布流程中单独授权。
