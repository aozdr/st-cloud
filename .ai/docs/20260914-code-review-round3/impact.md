# 影响分析

## 代码影响

| 区域 | 影响 | 兼容性 |
|---|---|---|
| `st-core` 上传/归档/文本/编辑器回调 | 失败后的规范对象由立即物理删除改为记录候选，由定时安全回收 | 对外 API 不变；对象删除延后 |
| `st-core` relay | 内存状态增加 committed/in-flight 序号语义，失败请求不再被提前确认 | 已提交重复包继续幂等成功；跳号/并发同序号返回冲突 |
| `st-desktop` SQLite | `transfer_mode`、`relay_chunk_size`、`relay_limit_kb` 增加可空迁移列 | 旧数据库自动补列；普通任务默认仍走直传 |
| `st-share` | 增加分享授权缩略图 endpoint | 新接口向后兼容；原 `/stream` 保留 |
| MySQL/H2 | 增加孤儿对象候选表 | 仅新增表和索引，不修改既有数据 |

## 数据与一致性风险

- 候选表的活动计数用于阻止宽限期内回收；删除前必须重新读取业务引用和活动上传会话。
- 候选记录进入 deleting 状态后禁止新的相同路径上传登记；安全检查失败时恢复为 pending。
- 对象存储操作在数据库事务外执行；提交成功后只清理候选记录，提交失败只标记候选。
- relay 仍是 JVM 内存中转。服务重启会丢失未完成中转状态，桌面端必须将该情况视为不可恢复并要求重新开始，不能切换为直传。

## API 影响

- 新增 `GET /api/share/access/thumbnail/{shareCode}`，接受现有分享访问参数及 `nodeId`，权限沿用分享密码、过期、下载开关和范围校验。
- `/relay-chunk` 和 `/relay-finalize` 请求/响应结构不变，仅收紧序号状态机错误处理。
- 既有普通下载、预览和文件上传接口路径不变。

## 运维影响

- 增加孤儿候选回收间隔和宽限期配置，默认宽限期按 1 小时处理，支持部署侧调整。
- 候选回收失败或安全条件未满足时保留记录并记录可检索日志。
