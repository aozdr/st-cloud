# 回归用例

- A1/T01：两个共享存储标签页依次续期，B 使用 A 的最新 pair，旧 pair 不被提交。
- A1/T02：两个标签页同时续期，模拟服务端一次性 refresh/CAS，成功结果一致，共享记录不被拒绝者清空；Web Locks 及无锁环境分别验证。
- A2/T03：A 退出时 B 更新未登录状态，sessionStorage 清空；A 换账号后 B 旧在途成功/拒绝不能覆盖或清理新会话。
- A2/T04：storage 事件迟到/过期修订不回滚最新 pair；暂时断网/503、存储写失败保留既有恢复语义；桌面认证 25 项及浏览器启动 8 项回归。
- A3/T05：回收混合上传者团队目录后 soft-delete 空间/成员，过期扫描包含目录，purge 删除子树，其它空间保持，重复 purge 幂等。
- A3/T06：相同墓碑状态下用户列表隐藏，恢复/永久删除被拒绝；系统 purge 正常态节点保持不变；原团队回收权限与并发矩阵回归。
- A4/T07：Web/desktop noEmit 类型检查；st-core 专项 H2 测试、SchemaConsistencyTest；可用时专用 MySQL 回收矩阵；独立代码/安全审查及独立证据复核。

所有数据写入限隔离测试夹具；不连接共享开发数据做删除实验。测试环境无法完成的项如实记录，不以旧报告替代当前证据。
# 独立复核后补充（设计契约保持 review-fixes-design-r1）

- T08：新页首次采用 R0 后，另一页在初始化镜像写入期间完成 R1 落盘；两种锁路径启动后均采用 R1，不提交 R0。相同窗口中另一页退出，新页清空内存和 sessionStorage。
- T09：A 成功轮换且共享 pair 写入单独失败，B 先续期旧 R0 并拒绝；两种锁路径均不得清空 A 内存最新对。A 恢复写入后再次续期/保存，B 能恢复最新 pair；协调元数据不包含 token。
- T10：协调元数据也无法持久化时，浏览器不消费一次性 refresh，返回临时错误并保留共享旧对；恢复存储后可重新续期。桌面原有写失败内存恢复仍通过。
- T11：旧请求已收到真实 HTTP 401，在清理 marker 扫描期间另一页完成新账号登录，两种锁路径的旧拒绝均不得删除或使新账号会话失效。普通永久拒绝仍使对应旧修订失效，旧页重载也不能恢复已拒绝的对。
- T12：A 的 R1 成功保存失败，共享仍 R0；A 随后消费 R1 收到明确401，当前已被拒绝的 R1 应失效、用户资料清空、上下文推进；另一页和重载也不能恢复更早已消费 R0。两种锁路径验证，未被拒绝的较新内存仍免受旧修订拒绝影响。
