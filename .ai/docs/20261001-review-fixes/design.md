# 定版设计 review-fixes-design-r1

目标、用户、场景、边界和完成标准见 requirement.md。本轮按 medium 执行，两个独立局部修正，接口/数据模型/产品状态机保持现有契约。

浏览器：读取共享的成对认证记录，监听同源 storage 变更，及时更新内存/sessionStorage 和认证订阅者；会话身份变化必须推进本页 generation，使旧请求失效。续期在浏览器可用的 Web Locks 下串行，锁后再读取共享版本，已经被其它标签页续期时复用其结果。对于无 Web Locks 的普通 HTTP 环境，以共享存储协调并发并在拒绝清理前复核最新共享记录；协调必须覆盖成功落盘前的窗口，不能仅增加一次 localStorage 读取。临时故障与磁盘失败保留现有恢复语义。Electron 主进程仍是唯一轮换者，不加入浏览器协调。

回收：空间锁查询允许锁定 soft-deleted 行，保持空间→节点锁序。用户 getAuthorizedRecycleNode 继续调用只返回有效空间/有效成员的 findRecycleManagedSpaceIds，因此恢复/用户永久删除不因墓碑锁可用而获准。系统 purgeNode 无用户授权要求，但继续锁后核对 RECYCLED；有保留期的扫描入口保持不变。物理不存在的空间沿用原错误，不扩大到删除正常文件。S3 仍通过提交后的现有事件处理。

兼容：HTTP、IPC、key 的既有认证记录和旧版 refresh 迁移保持；新增协调状态只承载会话身份/锁元数据，不另存令牌副本。数据库无 DDL，无迁移。风险为陈旧事件/拒绝覆盖新会话、旧标签页误触发退出及租户越权；由多标签交错与权限回归验证。

实现 scope 以 TASK 为准；没有未决范围、兼容性或风险裁决，confirmationRequired=false。

拒绝某修订也证明同会话更早的一次性令牌已不能恢复；拒绝标记匹配该修订及更早版本，不影响更高版本。共享记录较旧时，必须优先使本页已经明确拒绝的当前修订失效；只保护未被拒绝的较新内存对。

跨页自动拒绝不能对共享 pair 做“先检查后删除”：新登录可在检查后的任一存储操作间完成。浏览器只写按 server/session/revision 匹配的拒绝标记，内存同步与启动恢复只对该旧修订失效；共享新 pair 不被自动拒绝删除。显式用户退出仍保留原全局退出语义。拒绝标记不包含 token，既有 pair/HTTP/IPC 格式保持兼容。

独立复核的修正仍遵守上述契约：初始化共享基线与真正采用的 raw 使用同一次读取，避免两次读取间续期/退出留下不一致快照。浏览器在消费一次性 refresh 前持久化无 token 的轮换标记；若成功 pair 未能落盘或网络结果不确定，则保留标记，使其它页拒绝不能清空已成功的内存会话。完整 pair 保存后清理该会话已落后的标记。连协调标记也无法保存时，不发出浏览器续期请求，返回可重试错误并保留原对；Electron IPC 不受影响。这是写失败恢复和并发完整性的落实，无接口、范围或数据模型决策变化。
