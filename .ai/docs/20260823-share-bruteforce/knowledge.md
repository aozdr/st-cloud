# Knowledge：分享防枚举复盘

## 核心结论

百度私密分享的防枚举不靠提取码强度，而靠「长随机分享标识不可枚举 + 服务端频控/验证码」。

## 落地要点

- 分享标识：12 位 57 字符集（排除易混 `0/O/1/I/l`），空间约 1.6×10^21，SecureRandom 生成 + 唯一索引重试。
- 提取码防爆破：单码/单 IP 双维度失败计数（滑动窗口）→ 达阈值锁定；失败达阈值后强制图形验证码；成功访问清除计数。
- 全局配置：`sys_config` key-value 表，后台「系统管理 → 分享安全」可改，写入走白名单前缀。
- 不存在/已取消：直接返回，不消耗计数资源。
- 错误码：`3005` 尝试次数过多；`3006` 请完成验证码。

## 复用组件

- `CacheFactory`：多实例 Redis 一致、单实例内存兜底，供计数/验证码答案存储。
- `SysConfigService`：全局配置读写 + TTL 缓存 + 白名单更新。

## 后续建议

- 生产开启 Redis 缓存保证多实例一致性。
- 网关配置可信 `X-Forwarded-For`。
- 验证码可升级滑块/第三方行为验证。
