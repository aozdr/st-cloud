# Security Review：分享防枚举

结论：PASS（含后续建议）

## 威胁与缓解

| 威胁 | 缓解 | 状态 |
|---|---|---|
| 分享标识可枚举 | 分享码 4 位→12 位 57 字符集（约 1.6×10^21），不可枚举；旧码兼容 | 已实现 |
| 提取码暴力枚举 | 单分享码失败达阈值锁定、单 IP 总失败锁定 | 已实现 |
| 自动化批量探测 | 失败达阈值后强制图形验证码；验证码一次有效 | 已实现 |
| 配置被篡改 | 更新仅白名单前缀 + `admin:share:security` 权限 | 已实现 |
| 越权枚举多个分享码 | 公开访问统一经 `validateShareAccess` 守卫 | 已实现 |

## 安全要点

- 频控采用滑动窗口计数（含时间戳），按分享码与 IP 双维度，防单点/分布式枚举。
- 分享不存在/已取消直接返回，不消耗计数资源（用户决策 P3）。
- 验证码答案不落库、一次性销毁，降低重放风险。
- 校验入口统一，避免绕过（`getDownloadUrl`/`streamShareFile`/`listShareFiles`/`editorConfig` 均走守卫）。

## 建议（非阻塞）

- 生产启用 Redis 缓存以消除多实例计数不一致窗口。
- 网关统一配置可信 `X-Forwarded-For`，或改为从 `RemoteAddr` 透传。
- 验证码后续可升级滑块/第三方行为验证以提升抗自动化能力。

## 结论

分享访问控制的安全薄弱点（枚举、暴力、自动化探测）均已加固，可以接受。
