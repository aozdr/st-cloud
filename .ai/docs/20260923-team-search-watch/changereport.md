# 变更报告

- Revision：`tsw-design-r4` / `tsw-code-r8`

## 本轮集成修正

1. `ReliableEventPublisher.publishFileIndex` 在 Outbox 快照生成前以已认证 tenantId 补齐内存实体缺失值；认证上下文与节点租户冲突、或两者均缺少有效租户时均在写入前拒绝。
2. 增加 H2 集成测试覆盖补齐成功、租户冲突拒绝、无可信租户拒绝三种分支，确认拒绝时没有索引/relay 事件或 Outbox 行。
3. `NotificationController` 限制通知分页 `page>=1`、`1<=size<=100`，并增加验证在参数非法时不触发 mapper/通知映射服务的控制器测试。
4. 修正 `SchemaConsistencyTest` 对多列 `ALTER TABLE ... ADD COLUMN` 的解析，使 SQL 43 的 notification 列都参与 H2/MySQL 静态列比对。
5. 需求、程序设计和测试用例文档更新了上述安全边界；知识库同步团队搜索、关注投递、通知安全目标、API 与数据表。
6. 独立体验方案评审发现追加分页游标过期时缺少重搜入口，以及通知目标请求可能乱序导航。搜索页现在对已有结果的游标错误同样显示“重新搜索”；通知点击采用最新选择序号，过时 target 响应或组件卸载后不导航。设计和测试用例补齐这两项行为。
7. 独立代码评审指出团队搜索候选逐条核权反复查询成员、祖先和规则。候选扫描改用单次请求的权限读取上下文；共享祖先与规则只在这次扫描复用，响应前仍走无缓存的即时核权。补充兄弟节点复用次数及最终核权测试。
8. 搜索回归发现 Base64URL 非规范编码可能解出同一签名字节。游标解析现在要求 payload 和签名都与无填充规范编码一致，避免同一签名的不同文本被接受。

## 已集成的功能范围

当前工作树包含团队全文搜索（租户/空间/目录约束、当前 ACL 复核、HMAC 游标、候选预算、索引元数据比对）、个人关注与可靠变更通知（事务捕获、订阅代际、重试幂等、通知实时核权）、前端团队搜索/关注列表/通知入口及 SQL 43/H2 schema。该主体实现和历史执行记录来自之前的任务阶段；本报告不把它们改写为本轮由当前模型首次编写。
