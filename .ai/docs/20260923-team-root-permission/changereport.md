# 变更报告

## 背景与原因

用户日志显示 `folderNodeId=0` 的 PUT 请求进入 `requireFolderNodeInSpace`，查询 `file_node.id=0` 为空后抛出“节点不属于该空间”。页面将 `0` 明确用作“空间根目录权限”，服务端原校验未识别虚拟根目录。

## 修改

- 管理员权限校验后接受 `nodeId=0`，正数节点继续核实归属和状态。
- 根规则的读取与覆盖删除限定 `space_id`；不修改表结构及 API 格式。
- 内容操作的 `parentId=null` 映射到虚拟根 `0`，根规则可用于根目录列举、新建文件夹和文件。
- 普通解析和 fresh 核权在父链到根后加入本空间根规则；两条路径均核实节点归属，断链、循环及跨空间时拒绝，20 层目录的常规解析也能读取根规则。
- 实际内容授权使用无共享缓存的 fresh 解析，回收站节点及祖先立即拒绝，避免旧缓存短时放权。
- 补充空间隔离、非管理员拒绝、深目录及断链用例，并更新接口和业务知识。

## 影响与风险

空间根规则现在会对该空间的节点生效，属于权限增强。现有规则只增强不剥夺角色权限；根规则为空时行为不变。需在部署时使用包含修复的后端，未执行生产迁移或数据修改。
