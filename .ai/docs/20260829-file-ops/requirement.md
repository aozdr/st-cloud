# 需求分析：文件跨空间操作与元数据增强

> 迭代：20260829-file-ops
> 状态：待用户确认（未确认不得进入设计/实现）
> 范围：转存 / 元数据编辑 / 跨空间移动复制 / 排序增强（不含安全类，如加密、水印、访问控制加固）

## 1. 背景与目标

星云盘已覆盖单空间（个人空间或团队空间）内的文件管理，但存在四个业务能力缺口：

1. **转存 / 保存到我的网盘**：用户看到他人分享链接后，无法一键把分享内容存入自己的空间，只能下载后重新上传。
2. **元数据编辑**：文件只有文件名、大小、时间等系统字段，不支持自定义标题、描述、标签、封面。
3. **跨空间移动/复制**：个人空间与团队空间之间互相隔离，无法把文件移入/复制到另一个空间。
4. **排序增强**：列表视图仅支持名称/大小/时间排序，缺类型列排序与手动拖拽排序。

目标：补齐这四项业务能力，提升协作与内容组织效率，同时保持现有接口与数据兼容。

## 2. 用户与场景

| 角色 | 场景 |
|------|------|
| 个人用户 | 把他人分享的文件/文件夹一键转存到个人空间 |
| 个人用户 | 把个人文件移入团队空间协作；把团队产生的成果复制回个人空间 |
| 个人用户 | 给文件加标题/描述/标签/封面，便于识别与检索 |
| 团队管理员/编辑者 | 在团队空间内给文件加元数据；跨空间移动/复制需目标空间写权限 |
| 所有用户 | 列表视图按类型排序，或自定义手动排序 |

## 3. 功能边界

### 3.1 转存 / 保存到我的网盘

- 支持对分享链接（文件或文件夹）执行「保存到我的网盘」。
- 目标位置：默认个人空间的当前目录，也可选择指定个人目录或团队空间目录。
- 需携带分享提取码（私密分享）与分享访问校验；仅当分享权限点含 `view`（可读）时允许转存。
- 转存为复制语义：不消耗/转移源分享内容，目标空间产生新节点并增加对象引用计数。

不包含：转存后自动通知原分享者、转存配额之外的批量超大目录预估、分享到社交平台。

### 3.2 元数据编辑

- 支持对文件/文件夹设置：`title`（标题）、`description`（描述）、`coverPath`（封面图）、`tags`（标签，可多选/新建）。
- 元数据为非关键字段：不影响文件内容、路径、权限判断；删除/移动/复制文件时随节点保留。
- 个人空间与团队空间均支持。

不包含：元数据检索的高级字段（如按描述全文检索）、协作字段（如状态、指派、截止日期）、模板化元数据（自定义字段结构）。

### 3.3 跨空间移动/复制

- 支持在「个人空间 ↔ 团队空间」之间移动/复制文件或文件夹（含递归子树）。
- 跨空间复制：目标空间新增副本，源不变。
- 跨空间移动：源从原空间移除，目标空间新增节点；`ownerId/spaceId` 按目标空间重设。
- 目标目录必须位于目标空间内且当前用户对该目录有写权限（个人空间本人可写；团队空间需对应权限点）。

不包含：跨租户移动/复制（不同租户物理隔离）、跨空间合并冲突策略（仍沿用「同名自动加序号」）。

### 3.4 排序增强

- 列表视图增加「类型」列排序（名称/大小/时间/类型，升/降序可切换）。
- 提供「文件夹优先」开关（前端已具备，保留）。
- 可选：手动拖拽排序（前端本地持久化，纯前端，不落后端排序字段）。

不包含：服务端自定义排序字段（`sort_order` 持久化）——本期按价值权衡暂不做，本地排序足够。

## 4. 业务规则

### 4.1 转存

- 私密分享必须校验提取码；校验不通过拒绝。
- 目标空间配额校验：三重配额（个人 / 团队 / 云盘总容量），转存按新增文件大小计入目标空间。
- 转存后目标空间产生 `file_node`，引用原物理对象（同租户 MD5 去重），`ref_count+1`。
- 同名冲突：目标目录已存在同名时自动加 `_1`、`_2` 序号（复用 `resolveNameConflict`）。
- 转存文件夹时递归拷贝子树，保持相对结构。

### 4.2 元数据

- `title` 仅做展示增强；`name` 仍为文件系统唯一命名，二者独立。
- 标签：同一节点可挂多个标签，同一节点不重复挂同一标签；标签按租户/空间隔离。
- 封面：`coverPath` 指向对象存储缩略图路径；缩略图生成沿用现有预览流程。
- 元数据删除：删除文件到回收站时元数据随之隐藏（跟随节点状态），永久删除时物理删除。

### 4.3 跨空间移动/复制

- 源空间校验：源节点的 `spaceId` 必须与声明一致，且当前用户对源有读权限（个人空间为本人；团队空间需对应权限点）。
- 目标空间校验：目标目录 `spaceId` 一致 + 当前用户对目标目录有写权限。
- 跨空间移动 = 复制到目标 + 删除源：需原子处理，任一步失败整体回滚。
- 配额处理：
  - 复制：目标空间扣减新增文件大小（三层校验）。
  - 移动：源空间释放所有量，目标空间扣减（三层校验），净增为 0（若同租户）。
- 去重引用：移动后 `file_node` 改为引用目标空间对象；同租户 MD5 去重，`ref_count` 保留为对象引用计数（对象不因移动而+/-）。
- 移动/复制文件夹时递归处理子树并重设 `path`。
- 编辑保护：正在编辑的文件禁止移动（沿用 `assertNotEditing`）。

### 4.4 排序

- 「类型」排序依据 `suffix`（文件）与 `nodeType`（文件夹优先），升/降序可切换。
- 排序为前端可配偏好，持久化到 `localStorage`，可同步到 URL query。
- 拖拽排序仅对当前目录生效，本地持久化；不写入服务端。

## 5. 数据与接口影响

- 数据模型新增：`file_meta`（标题/描述/封面）、`file_tag`（标签）、`file_node_tag`（节点-标签关联）。详见设计文档。
- 新增接口：
  - `POST /api/share/access/save/{shareCode}`（转存）
  - `GET/PUT /api/file/{nodeId}/meta`（元数据读写，含团队版本）
  - `POST /api/file/transfer`（跨空间移动/复制）
  - `GET /api/file/{nodeId}/tags`、`POST /api/file/{nodeId}/tags`（标签操作）
- 现有 `move/copy`（单空间）接口保持不变。

## 6. 异常场景

| 场景 | 处理 |
|------|------|
| 私密分享提取码错误 | 返回错误码，拒绝转存 |
| 分享已过期/被取消 | 拒绝转存 |
| 目标空间配额不足 | 拒绝操作并提示剩余空间 |
| 目标目录无写权限 | 拒绝操作并提示权限不足 |
| 移动时目标为自身/子目录 | 拒绝（沿用现有校验） |
| 同名冲突 | 自动加序号 |
| 元数据关联的文件已被回收站删除 | 元数据不展示，恢复后重新可见 |

## 7. 兼容策略

- 所有新增接口为增量接口；不改动现有单空间 `move/copy` 的入参与行为。
- 数据库变更通过新增 `docker/mysql/init/37_*.sql` 迁移脚本实现，不修改既有列；需同步 `st-core/src/test/resources/schema.sql`。
- 元数据为可选字段，旧数据缺少 `file_meta` 记录时返回空元数据，不影响现有文件列表/预览。
- 前端对旧版本浏览器/旧接口做兜底：无元数据时隐藏编辑入口。

### 8.1 裁决落地说明

- 转存目标：默认取当前浏览目录；弹窗允许切换空间（个人空间或用户参与且具写权限的团队空间）。
- 跨空间移动：允许在个人↔团队间移动；配额按「源释放 + 目标扣减」原子处理，目标空间不足时整体拒绝。
- 拖拽排序：只写前端 `localStorage`，不新增后端排序字段，不跨设备同步。
