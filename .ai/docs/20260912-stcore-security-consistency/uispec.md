# st-core 安全整改 UI/API 规格

## 1. 规格结论

本任务没有新增视觉页面或视觉组件。UI 影响来自上传接口边界和错误状态：个人上传与团队上传必须使用不同 API 命名空间，前端需要展示权限、参数超限、上传会话失效和冲突失败。

## 2. 页面与入口

| 场景 | 入口 | API 语义 | 视觉变化 |
|---|---|---|---|
| 个人文件浏览器 | 个人空间 | `/api/file/upload/*`，不得携带 team spaceId | 无 |
| 团队空间文件浏览器 | 团队空间 | `/api/team/{spaceId}/files/upload/*` 或等价显式团队路由 | 无 |
| 个人文件详情/版本/下载 | 个人文件页 | `/api/file/*`，只接受 personal node | 无 |
| 团队文件详情/版本/下载 | 团队文件页 | 需要显式 spaceId 和团队 ACL | 无 |
| 上传恢复 | 上传任务/队列 | 使用 uploadId；S3 uploadId 只作为兼容展示字段，不能作为授权依据 | 失效时显示可重试/重新上传 |

## 3. 状态设计

| 状态 | 触发条件 | 前端行为 |
|---|---|---|
| 成功 | scope、session、参数和数据库状态均通过 | 保持现有成功提示和列表刷新 |
| 无权限 | personal API 访问 team/他人节点，或团队 ACL 拒绝 | 显示无权限；不自动改用另一 API |
| 会话失效 | uploadId 不存在、过期、已完成或不属于当前用户 | 停止当前任务，提示重新初始化上传 |
| 参数错误 | 分片数、大小、MD5、文件名或 clientLimit 超限 | 在上传开始前展示可读错误 |
| 冲突 | 同名、乐观锁、版本号或目标树冲突 | 保留当前列表状态，提示刷新或重试 |
| 资源超限 | ZIP、解压、文件夹统计达到上限 | 展示“超出系统限制”或“统计不完整”，不得伪装成成功 |
| 网络/存储失败 | S3 操作失败 | 沿用现有失败重试/中止机制；服务端 session 状态为准 |

## 4. 客户端调用约束

- 不再把 `spaceId` 作为个人上传接口的可选透传字段使用。
- 团队上传从当前团队空间上下文取得 `spaceId`，调用显式团队路由；不从文件 node 或用户可编辑文本推断权限。
- 后续上传请求可以暂时保留 `s3UploadId`、`fileId` 字段以兼容旧客户端，但不能把它们当作安全凭据；服务端以 upload_session 为准。
- 失败响应必须可区分权限不足、参数错误、会话失效、名称冲突和资源超限。
- 不新增无限重试；冲突和会话失效最多由用户主动重新初始化。

## 5. 无障碍与一致性

- 复用现有错误提示、Toast、上传队列和加载状态组件。
- 错误提示不得包含他人 nodeId、路径、spaceId 或 S3 uploadId。
- 不改变现有文件列表、树、详情和版本页面的布局、颜色、字号或键盘操作。

## 6. 验收

- 团队空间上传请求可从显式团队入口完成，个人空间上传仍可从原个人入口完成。
- 团队用户误调用个人上传入口不会静默降级或写入个人空间，服务端明确拒绝。
- uploadId 泄露、spaceId 篡改和旧客户端携带错误 s3UploadId 时，界面显示失败，不产生上传副作用。
- P0/P1 的错误状态都有可观察的非成功结果，不能以空列表、伪成功或静默跳过代替。

## 7. 遗留问题点

无。路由兼容、范围和数据库预检方案已由用户确认。
