# 架构评估（程序设计前置）

- 版本：tsw-design-r1；作者：GPT-6；评估对象：需求与现有代码，不代表代码评审通过。

## 决策

1. ES 负责内容召回，数据库负责当前身份、节点状态与权限判定。拒绝把成员授权复制到 ES 作为最终依据；否则退出空间和权限收回会受异步索引延迟影响。
2. 新增团队搜索端点，保留个人搜索契约；采用授权后的游标分页，不把 ES total 暴露为可见结果总数。授权过滤之后做可见结果 lookahead。
3. st-common 定义 TeamFileAccessPolicy 接口；st-team 实现，st-search 使用。拒绝引入 st-core→st-team 循环依赖或在后台伪造登录用户 ThreadLocal。
4. 关注与通知实现位于 st-team（已依赖 st-core），核心写路径只发布一个数据库捕获事件。订阅投递队列与文件写事务一致；后台批处理落 notification。复用核心变更汇合点，但不复用前端可上报的活动日志，也不让 MQ 开关决定是否通知。
5. 新建 file_watch 和 file_watch_delivery，notification 添加可空幂等及目标字段。独立投递队列避免改动现有 MQ 重试语义和清理时机；代价是新增两张表与后台定时任务，范围可控。
6. 文件夹重命名/移动通过节点 ID 保持订阅；MOVE 明确记录旧 parentId，不能拿可变路径当身份。目录 DELETE/MOVE 的后代直接关注作为同事件候选，不展开成逐文件通知风暴。
7. 读取历史通知时二次授权，失权响应通用文案；缓存只允许请求内复用，不允许新链路依赖长 TTL 权限缓存实现即时撤权。

## 前置检查结论

方案可在现有模块方向内实现，无新第三方基础设施，无新收费服务；API 增量兼容。设计必须补充游标防篡改、候选扫描上限、订阅代际、持久重试、在线编辑/版本恢复事件覆盖、数据库与 ES 升级步骤。均在 design.md 中落实。不存在需用户裁决的未决范围或兼容性问题。
