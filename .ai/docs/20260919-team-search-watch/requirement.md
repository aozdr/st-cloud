# 团队全文搜索、文件关注与变更提醒需求文档

- 版本：1.0（tsw-design-r1）
- 日期：2026-09-16
- 作者：GPT-6 主线程
- 编码执行：GPT-5.6-Luna，max
- 状态：需求定版；未声明实现或验收完成
- 关联：`uispec.md`、`impact.md`、`architecture-review.md`、`design.md`、`testcases.md`

## 1. 目标与依据

让团队成员能找到自己有权阅读的团队文档，并主动关注重要文件或文件夹，在他人修改后收到站内提醒。两个功能共用现有文件、团队权限和站内通知能力。

已核实的现状：

1. `st-search/.../SearchController.java` 将当前用户 ID 传入搜索；`SearchServiceImpl.searchContent` 按 `ownerId` 过滤，不能表达团队成员对同事文件的访问权。
2. 当前正文索引支持 txt/pdf/doc/docx/xls/xlsx/ppt/pptx，大小上限 20MB；其他类型已有元数据搜索。此次沿用该范围，不承诺 OCR 或图片内容检索。
3. `TeamServiceImpl.resolveMyPermissions` 使用空间角色与文件夹授权并集。此次沿用这个模型，不新增拒绝规则或重做权限继承。
4. `NotificationController` 已有列表、未读数和已读操作；`NotificationBell` 每 30 秒读取未读数，但仅支持 team 类型跳转。代码中未发现文件关注订阅的完整实现。
5. 文件变更已有 `ReliableEventPublisher`，可覆盖新建、上传、移动、重命名和删除；版本恢复只发布索引事件，需要补齐相关通知触发。

以上为代码事实。尚无用户访谈、使用率及延迟基线，不虚构收益数据。

## 2. 用户与场景

| 用户 | 场景 | 期望 |
|---|---|---|
| 团队成员 | 只记得合同正文中的客户名称，不知道上传者或目录 | 在当前空间或指定文件夹中搜索文件名及正文 |
| 项目负责人 | 关注项目目录，成员不断上传与更新材料 | 收到新增、内容变更和目录结构变更提醒 |
| 文件协作者 | 关注某份设计文档 | 重命名、移动后仍关注同一文件 |
| 普通用户 | 关注个人文件或目录，存在他人通过已有分享编辑的场景 | 关注状态跨端保存；本人操作不产生自我提醒 |
| 空间管理员 | 成员退出、外部成员到期、权限调整 | 搜索和提醒不继续暴露失权内容 |

## 3. 本期范围与决策

### 3.1 团队全文搜索

- 从团队空间进入搜索，默认搜索当前空间；可限制为当前文件夹及后代。全局搜索页可切换个人/团队，团队模式选择一个已加入空间。
- 首版每次搜索一个空间；跨多个空间合并排名不在本期。个人搜索原接口与默认入口保持兼容。
- 保留类型、大小、更新时间筛选。正文匹配显示片段；名称、路径来自当前数据库状态。
- 团队结果采用“加载更多”，只展示已加载数量，不展示 Elasticsearch 原始命中总数。
- 正文索引异步更新；刚上传或刚修改的文件可能暂未出现。索引内容版本不匹配当前文件时不得使用旧正文命中或摘要冒充当前内容。

### 3.2 文件关注

- 支持当前用户有权查看的个人/团队文件及文件夹。匿名分享访问者不能创建关注；订阅不是授权，收藏与关注相互独立。
- 关注文件只跟踪该节点；关注文件夹跟踪文件夹自身及后代。关注绑定节点 ID，重命名、同空间移动后不丢失。
- 提供关注/取消关注操作及“我的关注”页，列表可分页查看并取消。失效项仅显示通用文案，仍可取消。
- 首版统一订阅全部支持的事件，不增加频率设置、静默时段或事件选择器。

### 3.3 变更通知

- 复用站内通知及现有轮询；不新增邮件、短信、Webhook、桌面系统推送。
- 通知来自服务端已提交的真实文件变更，不能依赖前端活动上报。
- 同一已提交事件给同一用户最多一条，即使同时关注文件及多个祖先文件夹。
- 不把多个不同事件按时间窗口合成一条。本期“去重”指同事件重试与重叠关注去重，不丢弃不同操作。
- 本人触发的变更不通知本人。匿名编辑无法可靠识别个人时标记为“协作者更新”，不猜测操作者身份。

## 4. 业务规则

### 4.1 搜索权限与结果

查询主体只能来自登录上下文，客户端不能指定其他 ownerId/userId/tenantId。团队搜索同时满足：同租户、空间有效、成员有效且未过期、节点属于选定空间、节点及祖先可访问、有效权限含 view；普通管理员身份不绕过空间成员校验。

隐藏节点及隐藏祖先下节点不进入新团队搜索。未完成上传、回收站、永久删除及祖先已回收的内容均不返回。指定文件夹必须属于该空间并可访问，越界目录返回统一无权/不存在响应。

权限在每次查询重新核对；不等待搜索索引权限同步。文件名、路径、正文片段、后续页标识均不得直接来自未经授权的 ES 命中。权限变更后的新请求不返回失权内容；已经显示在浏览器中的历史信息无法撤回。

分页游标绑定用户、租户、空间、目录和筛选条件，有效期 10 分钟；切换条件重新开始。正常稳定数据集不得因过滤掉无权命中而提前结束或重复结果。并发内容变化采用尽力一致，不承诺跨多次请求的历史快照。

为限制一次查询的工作量，最多检查 2000 个候选命中；达到上限仍无法确定完整一页及下一页状态时，返回明确“请缩小搜索范围”，不能返回伪造空结果或未授权总数。该值为首版配置默认值，不是实测容量指标。

### 4.2 订阅生命周期

| 操作 | 行为 |
|---|---|
| 重复关注 | 幂等成功，不生成多条有效订阅 |
| 取消关注 | 幂等成功，只能取消本人的订阅；未投递事件不再因该订阅通知 |
| 取消后再次关注 | 建立新的订阅身份，不补发上次关注期间的积压事件 |
| 重命名、同空间移动 | 节点关注保持；文件夹关注随文件夹移动 |
| 文件移入关注文件夹 | 产生移动提醒，后续变化纳入该目录关注 |
| 文件移出关注文件夹 | 最多提醒此次移出，后续变化不再由原目录关注触发；仍须当前可见才能显示细节 |
| 关注文件夹被删除 | 目录/后代关注变为不可访问；仅给符合当前成员与权限条件的订阅者通用不可用提醒，不披露回收内容 |
| 成员退出、到期或权限收回 | 停止投递细节；已有通知读取和目标打开时再次核权 |
| 文件恢复 | 原订阅若未取消且重新可见，则后续事件恢复提醒；不补发失权期间事件 |
| 取消关注后历史通知 | 历史通知仍保留，但读取细节仍受当前访问权控制 |

### 4.3 事件范围

| 业务动作 | 事件及提醒 |
|---|---|
| 创建文件/文件夹、上传完成、秒传、复制到目录、恢复 | CREATE：关注父目录的用户收到新增提醒 |
| 覆盖上传、同步覆盖、OnlyOffice/文本保存、历史版本恢复 | UPDATE：内容更新提醒；无实际变化或回滚不能通知 |
| 重命名 | RENAME：显示当前名称；不泄漏无权历史路径 |
| 移动 | MOVE：匹配原/新祖先与直接关注，按同事件用户去重 |
| 删除文件/文件夹到回收站 | DELETE：通用不可用提醒；不跳转到无权回收站 |
| 下载、预览、收藏、关注自身、未提交分片、失败操作 | 不通知 |

文件夹移动/删除只按一个根操作通知每个接收者一次；直接关注后代的用户也应受影响。复制会创建新的节点，不继承原文件订阅。永久删除不再重复发送已发生过的回收提醒。

### 4.4 可靠性与读取保护

- 事务回滚不生成提醒；数据库保存成功后，通知投递失败可重试，进程重启不能丢弃待投递记录。
- 同事件重复处理、工作进程并发处理不会生成重复通知。通知写入与投递完成标记需保持一致。
- 投递前核对仍有效的订阅、成员和目标权限；不得仅凭事件时的权限永久放行。
- 读取历史 FILE_CHANGE 通知时再核权。失权/删除时标题改为“关注内容已不可用”，清空名称、路径和跳转目标；未读条目可按原记录保留，不显示未授权内容细节。
- 查看通知不等于获得下载/编辑权；打开目标继续走原业务权限校验。

## 5. 可验收标准

| 编号 | 验收标准 |
|---|---|
| S01 | 成员可搜索同空间其他成员上传的文件名与受支持正文；非成员、到期成员、跨租户请求被拒绝 |
| S02 | 文件夹范围、角色及文件夹授权共同生效；隐藏/上传中/回收及不可访问祖先结果被排除 |
| S03 | 无权命中不泄漏名称、正文、路径或原始总数；失权后下一请求不可见 |
| S04 | 筛选与加载更多可用；无权命中位于前页时仍可找到后续有权结果；篡改/过期/跨用户游标被拒绝 |
| S05 | ES 故障与零结果区分；旧索引安全排除未迁移文档；正文版本过期不展示旧摘要 |
| S06 | 个人旧入口兼容；团队结果能进入正确团队目录，预览不误用个人上下文 |
| W01 | 文件/文件夹关注持久化、幂等；收藏不改变关注；匿名/无权对象不可关注 |
| W02 | 我的关注分页、有效/失效状态、取消操作可用；失效项无名称或路径泄漏 |
| W03 | 文件与祖先多重关注、重复事件及并发消费均为每用户每事件最多一条 |
| W04 | 表中各类成功写路径产生对应提醒；失败/回滚/未完成上传/只读操作不提醒；本人操作不自我通知 |
| W05 | 文件夹移动/删除覆盖后代直接关注，移出后不持续跟踪，重命名/移动保持节点订阅 |
| W06 | 取消及重新关注不接收取消前积压事件；退出/到期/失权后停止细节提醒 |
| W07 | 新通知与已存在通知读取、跳转均核权；删除或失权返回通用不可用状态 |
| W08 | 待投递任务重启后可恢复，失败有重试与可定位日志，不影响已提交文件的最终状态 |
| U01 | 桌面及窄屏入口可用；键盘可操作；加载、错误、空状态与权限变化有明确反馈 |
| E01 | 新 SQL、H2 schema、SchemaConsistencyTest、MySQL 迁移前后对比与版本记录完整；前后端验证通过 |

## 6. 成功标准与风险

发布门槛：上述验收场景通过，权限负例零泄漏，回滚零提醒，同事件无重复。正常无积压环境下提交至通知可查询目标不超过 60 秒（含现有轮询），需要实测验证；搜索延迟须记录测试数据规模和实测结果，不用未测的 P95 数字作为已达成结论。

主要风险：旧索引缺少租户/空间字段；现有权限缓存与成员过期处理不能直接代替查询时校验；异步任务不带登录上下文；目录移动及删除仅发布根事件；在线编辑的操作者身份不一定来自当前 HTTP 登录用户。设计必须分别处理。

## 7. 本期不包含

跨空间聚合排名、OCR、语义/AI 搜索、历史版本正文搜索、分享匿名关注、邮件/Webhook、每日摘要、批量自动关注、重做权限模型、通知中直接编辑/下载、文件保留策略或删除现有业务数据。

## 8. 遗留问题与定版依据

无需用户裁决的未决范围/兼容性风险为 0。本期采用上文明确的最小完整范围；用户已选择两项功能并要求设计后实施。部署到生产及生产数据库迁移不在授权内。性能阈值需要验证，是验收工作而非新增产品决策。

自检：需求强项是权限和通知生命周期边界；最需要实施验证的是大空间权限过滤成本、全部写入口的事件覆盖和迁移环境可用性。
