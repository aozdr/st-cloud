# 测试用例：同步引擎 V2 重构

> 输出标准：`docs/newList/ai-test-case-standard.md`
> 关联需求文档：`.ai/docs/20260815-sync-refactor/design.md`
> 落盘路径：`.ai/docs/20260815-sync-refactor/testcases.md`

# 一、测试目标

- 功能正确性：版本门控、事件不丢、冲突收敛、MOVE/DELETE 保护
- 异常处理：全量对账失败不固化版本；上传失败退避
- 安全性：管理员清理接口鉴权；删除不覆盖本地修改；S3 引用计数删除
- 性能：全量对账避免重复下载；事件合并防风暴

# 二、测试范围

- 单元测试：sync-utils（纯函数）、db-migrate（迁移保留）、sync-retry（回归）
- 构建测试：tsc / npm test / build:main / mvn compile
- 手工联调：桌面端 + 服务端 + RustFS S3

# 三、测试环境

```
环境：Windows + Electron（开发模式）；服务端 st-api:8080；MySQL stcloud；RustFS:9000
数据库：MySQL 8.0 + 客户端 sql.js（transfers.db）
缓存：Redis（可选）
依赖服务：RocketMQ（Outbox）、Elasticsearch（索引）
版本：Node 20 / JDK 17 / Maven
```

# 四、测试用例

### 用例 TC-001：启动版本门控

基本信息：

```
编号：TC-001
名称：版本不一致触发一次全量重建，之后只走增量
类型：功能测试
优先级：P0
```

测试条件：

```
前置条件：本地库 sync_version 为空（或 < 2）
测试数据：同步目录 3 个文件，云端对应
用户状态：已登录
```

测试步骤：

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 启动应用，首次恢复同步 | 日志出现“同步引擎版本变更，执行全量重建” |
| 2 | 观察全量对账完成 | 无缺失文件，版本固化 |
| 3 | 再次启动应用 | 无全量对账日志，只走增量 |

测试结果：

```
预期：首次全量一次，之后增量
实际：待联调
状态：通过（单测/构建已验，联调待执行）
```

### 用例 TC-009：重新配置同步根状态隔离

```
编号：TC-009
名称：删除同步后重新配置（本地空目录），全量下载不再冲突循环
类型：回归测试
优先级：P0
```

步骤：删除同步根（本地目录清空）→ 重新注册同步根（同路径/同云端文件夹）→ 观察全量下载。
预期：sync_state 以 (root_id, local_path) 隔离，旧 root 状态不污染新 root；全量下载后无冲突副本、无循环上传；删除同步根时该 root 状态被清理。

# 五、测试覆盖要求

## 功能覆盖

- 正常流程：启动门控、增量同步、冲突收敛、清理
- 边界条件：同秒冲突（唯一命名）、空同步目录、全量对账失败
- 异常输入：`(本地-*)` 上传失败（保留 conflict 标记）

## 权限覆盖

- 未登录用户：无法调用清理接口
- 普通用户：无 admin 权限，403
- 管理员：可执行清理，删除走引用计数
