# UI 设计文档

> 输出标准：`docs/newList/ai-ui-design-document-standard.md`
> 落盘路径：`.ai/docs/20260813-upload-rate-throttle/uispec.md`
> 本任务以服务端逻辑为主，UI 改动集中在「上传面板状态反馈」，不新增页面。

# 一、页面定位

本功能不新增页面。改动对象为现有上传传输面板（`UploadPanel` 组件 + `useUpload` Hook + 桌面端任务卡片），核心目标：在**低速率中转模式**下，让用户清楚感知「正在限速传输」而非「假死」。

# 二、信息层级

上传任务卡片在中转模式下展示以下信息（按层级）：

1. **主状态**：文件名 + 进度条 + 百分比（与现有一致）
2. **限速标识**：进度条下方显示限速值徽标（如「限速 100 KB/s」），中转模式下高亮
3. **传输模式提示**：中转模式时显示「限速中转上传中」次级文案；直传模式不显示
4. **预估剩余时间**：基于限速值与剩余字节数估算（中转模式下速率可预测，估算更准）

# 三、交互

| 状态 | 触发条件 | 展示 |
|------|---------|------|
| hashing | 计算MD5 | 现有「校验中」 |
| pending | 等待秒传结果 | 现有 |
| uploading（直传） | rate≥5MB 或不限速 | 现有进度条 + 「上传中」 |
| uploading（中转） | 0<rate<5MB | 进度条 + 「限速中转上传中 · 限速 X KB/s」+ 预估剩余时间 |
| paused / merging / completed / failed | 同现有 | 同现有 |

- 中转模式下进度条按已接收字节平滑推进（服务端逐块确认），而非按分片跳变。
- 失败时若为限速超时，错误文案明确「传输超时，限速值过低」，引导用户调高限速或等待。

# 四、视觉规范

- 限速徽标：使用现有 design system 的 `warning`/`info` 色调小标签，不引入新色。
- 中转模式提示文案：次级文字色（muted），字号与现有任务次级信息一致。
- 不新增图标；复用现有上传图标。
- 进度条颜色、动画与现有完全一致，避免视觉割裂。

# 五、状态管理

- `UploadTask` 类型新增可选字段 `transferMode: 'direct' | 'relay'`，由 init 响应设置。
- `effective.uploadSpeedLimit` 已有，中转模式下用于显示限速徽标与预估时间。
- 桌面端 `TransferTask` 同步新增 `transferMode` 字段，经 IPC 传递。

# 六、无障碍与边界

- 限速状态信息以文字呈现（非仅颜色），确保色弱用户可读。
- 极低速率下预估剩余时间可能很大（如数小时），格式化为「Xh Ym」，超过 24h 显示「>24h」。
- 中转模式不影响暂停/取消等现有操作。
