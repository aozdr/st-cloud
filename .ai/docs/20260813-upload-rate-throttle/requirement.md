# 一、需求概述

## 1.1 功能名称

上传低速率强制限速中转

## 1.2 背景说明

管理端可对用户/角色配置上传限速（KB/s）。当前上传采用 **presigned URL 直传 S3**，服务端用令牌桶门控「何时签发分片 URL」，客户端拿到 URL 后直传 S3，传完调 confirm 释放配额。

该架构在限速值 ≥ 分片大小（5MB）时工作正常；但当**强制限速值低于分片大小**时存在固有缺陷：

1. 令牌桶容量被 `Math.max(chunkBytes, rate)` 撑到 chunkBytes（5MB），首片满容量放行 → 整个 5MB 分片以网络满速直传 S3，**瞬时速率突破限速值**。1KB/s 限速下，每攒够令牌就突发一次 5MB。
2. `retryAfterMs` 被封顶 5s，低速率下真实等待可达数千秒 → 客户端高频空轮询，单分片上千次无意义 HTTP 请求。
3. `simpleUpload`（<100MB 小文件）走服务端 `putObject` 中转但**完全未接限速**，小文件直接绕过限速。

强制限速是安全/合规需求，**必须真实达成瞬时速率约束**，而非「时间平均速率近似」。presigned 直传的限速粒度下限就是分片大小（5MB），无法在直传路径内突破。

## 1.3 用户角色

| 用户角色 | 权限 | 使用场景 |
|---------|------|---------|
| 普通用户 | 被管理端强制限速 | 在低速率限速下上传文件，期望限速真实生效 |
| 普通用户 | 客户端自设限速 | 自愿限速上传，期望节流真实 |
| 管理员 | 配置限速规则 | 设置用户/角色上传下载速率上限，含极低速率 |

# 二、业务需求分析

## 2.1 用户故事

- 作为被强制 1KB/s 限速的用户，我希望上传时真正按 1KB/s 传输（瞬时速率不超限），而非每 5MB 突发一次，从而限速能真实生效、合规可审计。
- 作为自设 100KB/s 限速的用户，我希望上传节流真实生效，而非突发。
- 作为管理员，我希望配置的任意速率限速（包括低于 5MB 的）都能被严格执行。

## 2.2 功能列表

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F1 | 低速率中转模式判定 | init 阶段解析有效限速，rate<分片下限时返回中转模式标志与小块参数 | P0 |
| F2 | 服务端中转逐块节流接收 | 客户端发小块到服务端，服务端按限速值逐块阻塞节流接收 | P0 |
| F3 | 分片缓冲与 multipart 写入 | 服务端缓冲接收数据，攒够 multipart 下限（5MB）后 uploadPart，末片无下限 | P0 |
| F4 | 临时文件生命周期管理 | 中转缓冲文件按 uploadId 隔离，合并/失败/超时后即删，无泄漏 | P0 |
| F5 | 客户端自限速真实节流 | 客户端自限速场景同样走中转（服务端统一节流） | P1 |
| F6 | simpleUpload 限速接入 | 小文件中转路径接入限速节流（修复现存绕过） | P1 |
| F7 | 客户端中转模式状态展示 | 上传面板在中转/等待限速配额时给出明确状态，避免假死 | P1 |

## 2.3 业务流程

### 正常速率（rate=0 不限速 或 rate ≥ 5MB）—— 保持现状

```
客户端 init → 服务端返回 presigned 直传模式
客户端逐片申请 chunk-url → 直传 S3 → confirm → merge
```

### 低速率（0 < rate < 5MB）—— 中转模式

```
客户端 init → 服务端解析限速，判定 rate<5MB，返回中转模式 + 小块大小
客户端将文件切成小块（如 min(rate*N, 5MB)），逐块 POST 到中转接口
服务端逐块阻塞节流接收（acquireUpload 按字节 pacing）→ 缓冲到临时文件
服务端缓冲攒够 5MB → uploadPart 写入 S3 multipart（末片不受 5MB 限制）
全部接收完 → completeMultipartUpload → 删除临时文件 → 释放配额
```

# 三、功能边界

## 包含范围

- 有效限速值低于分片下限（5MB）时的上传服务端中转路径
- 客户端自限速场景的真实节流（统一走服务端中转节流）
- `simpleUpload` 小文件中转路径的限速接入（修复绕过 bug）
- 中转临时文件的隔离、清理与生命周期管理
- 上传面板中转模式的状态反馈

## 不包含范围

- 下载限速（已服务端中转 + 逐块阻塞节流，已达标，无需改动）
- 正常速率 presigned 直传路径（保持不变）
- 限速规则管理 UI（已有 SpeedLimitController）
- 分享链路预签名下载绕过限速（独立问题，不在本任务范围）

# 四、业务规则

- **有效限速** = `capRate(服务端限速, 客户端限速)`，取最严格（最小且 >0），全为 0 则不限速。
- **模式判定**：`rate == 0`（不限速）或 `rate >= CHUNK_SIZE(5MB)` → presigned 直传；`0 < rate < CHUNK_SIZE` → 中转模式。
- **小块大小**：中转模式下客户端发送的小块大小取 `min(max(rate * 窗口秒数, 8KB), CHUNK_SIZE)`，平衡节流精度与请求频率；窗口建议 1~2 秒。
- **S3 multipart 约束**：非末片 ≥ 5MB（S3/MinIO 硬约束），末片无下限。服务端缓冲按此攒批。
- **权限校验**：中转接口与直传一致——仅文件 owner 或租户管理员可操作对应 uploadId。
- **配额**：中转模式配额校验与扣减逻辑与直传一致（init 时校验，merge 后扣减）。
- **限速值单位**：KB/s，0 = 不限速（哨兵值，非「禁用」）。

# 五、异常场景

| 场景 | 处理方式 |
|------|---------|
| 限速配置为 0 | 不限速，走 presigned 直传 |
| 中转过程中客户端断连 | 服务端超时检测后清理临时文件，abort multipart |
| 临时文件写入失败（磁盘满） | 返回错误，删除已写临时文件，abort multipart |
| S3 uploadPart 失败 | 重试有限次后失败，清理临时文件 + abort |
| 限速值极低（如 1B/s） | 仍走中转，节流等待可能很长，客户端需超时保护并提示 |
| 中转接口未鉴权访问 | 返回 401/403，不接收任何数据 |

# 六、非功能需求

## 性能

- 正常速率上传：性能与行为不变（presigned 直传，不经服务端字节流）。
- 低速率上传：服务端承担中转带宽（但低速率下带宽本就被限到很小，开销可控）；缓冲用本地临时文件，单用户峰值磁盘占用 ≈ 5MB（一个 multipart part 缓冲量）。
- 中转接口请求频率：小块传输，每秒约 1/N 个请求（N=窗口秒数），远低于当前 5s 空轮询。

## 安全

- 中转接口必须鉴权 + owner/租户权限校验，防止越权上传到他人 uploadId。
- 临时文件按 uploadId 隔离存放，路径不可由客户端控制（防路径穿越）。
- 临时文件用完即删，失败/超时也删，防止磁盘泄漏与信息残留。
- 限速强制在服务端执行，客户端无法绕过（中转模式下服务端控制接收速率）。

## 可维护性

- 限速判定集中在一处（init 阶段），模式切换对客户端透明（init 响应携带模式）。
- 两套上传路径（直传/中转）共用 init/merge/配额逻辑，仅中间传输路径不同。

# 七、验收标准

- Given 用户被服务端限速 1KB/s，When 上传 10MB 文件，Then 上传走中转模式，任意时间窗口内瞬时速率不超过 1KB/s（允许节流步进内的小波动，非 5MB 突发）。
- Given 用户不限速（rate=0），When 上传文件，Then 走 presigned 直传，行为与改动前完全一致。
- Given 用户自限速 100KB/s（<5MB），When 上传文件，Then 走中转模式，瞬时速率不超 100KB/s。
- Given 用户限速 10MB/s（≥5MB），When 上传文件，Then 走 presigned 直传。
- Given 中转上传中途客户端断连，Then 服务端在超时后清理临时文件并 abort multipart，无磁盘泄漏。
- Given simpleUpload 小文件（<100MB）上传，Then 接入限速节流，不再绕过限速。
- Given 中转接口被非 owner 访问，Then 返回权限拒绝，不接收数据。

# 八、风险分析

| 风险 | 影响 | 解决方案 |
|------|------|---------|
| 中转路径增加服务端带宽/磁盘开销 | 低速率下开销可控；正常速率不受影响 | 仅低速率走中转；缓冲量上限 5MB |
| 两套上传路径维护复杂度 | 需保证 init/merge/配额逻辑共用 | 共用编排层，仅传输路径分支 |
| 临时文件泄漏 | 磁盘占用增长 | uploadId 隔离 + 超时清理 + 失败即删 |
| 极低速率下上传极慢，用户误以为假死 | 体验问题 | 客户端状态展示 + 超时保护 |
| 中转接口被滥用（大流量打服务端） | 服务端压力 | 限速节流本身限制接收速率 + 鉴权 |
