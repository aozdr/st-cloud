# UI / 体验约束说明

## 结论

本轮不修改 UI 视觉、页面布局、组件层级或交互样式。体验变化仅限上传正确性、冲突提示、并发冲突响应和 Archive 超限错误的准确性。

## 允许的行为变化

| 场景 | 用户可见结果 |
|---|---|
| 完整 MD5 | Web/Desktop 对同一文件的秒传判断一致；大文件可能等待更久 |
| 同名 scope | 不同个人用户或不同团队 space 的同名文件不再互相阻塞 |
| merge vs abort | 合并已开始时 abort 显示既有冲突错误，不出现“已取消但仍完成”的矛盾状态 |
| Archive 超限 | 显示文件过大/输入压缩包超过限制；不改变页面样式 |
| simpleUpload | 100MB 阈值与错误文案一致 |

## 禁止事项

- 不改 CSS、视觉 token、页面布局、上传面板结构或桌面 UI。
- 不新增需要前端路由、组件或公开 API 的产品功能。
- 不将安全/一致性失败隐藏为成功提示。

## 验收

- 现有 UI 构建通过。
- 行为错误沿用现有错误展示链路，不引入新的视觉方案。
