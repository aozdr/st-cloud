# 需求文档：文件分享可选过期时间（20260813-share-expiry）

## 背景

星云盘（st-cloud）文件分享需要支持"可选过期时间"：创建分享时用户可选择有效期（1 天/5 天/7 天/无限期），到期后分享链接自动失效，任何访问（访问、下载、目录列表、流式预览）都应被拒绝并提示"分享已过期"。

现状核实结论：该功能在代码中已基本实现（数据库 `file_share.expire_at` 列、后端 `expireAt` 字段与 `SHARE_EXPIRED` 校验、前端分享弹窗有效期选项均已存在），但存在以下缺口：

1. 没有任何自动化测试覆盖分享模块（st-share 无 `src/test`）。
2. 创建/更新分享时未校验过期时间必须晚于当前时间，可生成"已过期"的分享。
3. 更新接口无法清除过期时间（`expireAt=null` 不生效），设置有效期后无法改回"永久"。
4. 分享管理页将已过期的分享仍展示为绿色"有效"，与真实状态不一致。
5. 前端以 UTC ISO 字符串（带 `Z`）提交过期时间，与后端 `LocalDateTime`（上海时区墙钟）语义不一致，存在解析失败或 8 小时偏移风险。
6. H2 测试 schema 缺少 `file_share` 表，无法支撑分享模块集成测试。

## 用户故事

- 作为文件所有者，我可以在创建分享时选择有效期（1 天/5 天/7 天/无限期），以便控制链接的可用时长。
- 作为文件所有者，我可以在分享管理页看到分享是否已过期，避免误以为链接仍有效。
- 作为访客，当分享已过期时，我访问/下载/预览应看到明确的"分享已过期"提示，而不是文件内容。

## 功能范围

### 本迭代包含

- 创建分享：支持可选过期时间（已有），新增"过期时间必须晚于当前时间"校验。
- 更新分享：支持修改过期时间；新增"清除过期时间（恢复永久）"能力。
- 分享访问控制：过期分享的访问/下载/目录列表/流式预览均返回 `SHARE_EXPIRED(3002)`（已有，需测试锁定）。
- 分享管理页：已过期分享展示"已过期"状态。
- 时间格式：前端改为提交本地时间 `yyyy-MM-ddTHH:mm:ss`（无时区后缀），与后端 `LocalDateTime` + 上海时区语义一致。
- 测试：st-share 集成测试覆盖过期时间完整链路；H2 schema 补齐 `file_share` 表。
- 死代码清理：移除 `ShareAccessVO.isExpired`（后端恒为 false，前端无使用）。

### 本迭代不包含

- 不做数据库结构变更（`expire_at` 列已存在，无需迁移脚本）。
- 不做后台定时任务自动清理/标记过期分享（访问时惰性校验已满足需求）。
- 不改动团队邀请（Team Invite）等其他模块的时间处理（存在同类时区隐患，另立迭代处理）。
- 不在分享管理页新增"编辑有效期"完整表单（当前无编辑 UI；清除/修改过期能力通过 API 提供并被测试覆盖）。

## 验收标准

1. 创建分享时可不传 `expireAt`（永久），也可传未来时间（有限期）；传过去时间返回业务错误。
2. 分享过期后，`accessShare`/`getDownloadUrl`/`listShareFiles`/`streamShareFile` 均返回 `SHARE_EXPIRED(3002, "分享已过期")`。
3. 更新分享可修改 `expireAt`；`clearExpireAt=true` 可将分享恢复为永久。
4. 分享管理页对已过期且未取消的分享展示"已过期"而非"有效"。
5. 前端提交的过期时间为本地时间 `yyyy-MM-ddTHH:mm:ss`（无 `Z`），后端可正常解析并持久化。
6. `mvn test`（含 st-share 新增测试）全绿；`st-web` 前端构建通过。
7. 产出 design.md / testcases.md / changereport.md / codereview.md / security.md / testreport.md 归档至 `.ai/docs/20260813-share-expiry/`。

## 影响范围

- 后端：`st-share`（DTO、Service、测试）、`st-core` 测试资源 `schema.sql`。
- 前端：`st-web`（ShareDialog、ShareManagePage、types）。
- 数据库：无 DDL 变更。
