# CR-02 团队自定义角色测试用例

来源：[需求](../20260924-code-review-design/CR-02/requirement.md)、[设计](../20260924-code-review-design/CR-02/design.md)。全部 NOT RUN。S1 所有者 O、普通成员 M、外部成员 E；有效自定义角色 R 使用字符串 `9007199254740993`，R2 使用 `9007199254740995`；Rview={view}、Rempty={}。目录 D 可设置 all/member/role ACL。每条用例单独恢复成员、角色与 ACL。建议 API/服务集成、MySQL 并发及浏览器网络断言。

| ID / 优先级 / 映射 | 前置条件与步骤 | 预期结果与证据 |
|---|---|---|
| TC02-01 / P0 / A02-1 | 创建大 ID 角色；直接邀请 M 使用该角色；读取成员并重新打开 UI。 | DB、响应 JSON、选项 value、组件状态、提交参数逐字符保持原字符串，无 Number/parseInt 截断；正确名称回显。 |
| TC02-02 / P0 / A02-1、A02-5 | 创建指定 R 的邀请链接并接受，读取邀请和成员。 | 两表与两种响应 role 精确一致；成员实际获得 R 权限，非默认查看者。 |
| TC02-03 / P0 / A02-4 | 将 M 从 R 切换到 R2，两者基础权限相同但各自匹配不同目录 ACL。 | 下次鉴权按 R2 的 ACL；不能沿用旧角色规则；UI 成功后回显 R2。 |
| TC02-04 / P1 / R02-1 | 参数化邀请、链接、成员更新：分别传数值 0/1/2 与字符串 0/1/2；邀请另省略 role。 | 旧预设请求兼容，响应/前端统一字符串；省略邀请 role 按约定默认查看者。 |
| TC02-05 / P0 / R02-3 | 对 JSON 与 query 入口分别传 null、空串、负数、浮点、科学计数、布尔、超 Long 值；JSON 另传大自定义数字而非字符串。 | 全部拒绝，不新增成员/邀请或改变原角色；不得发生舍入后误命中另一角色。 |
| TC02-06 / P0 / A02-3 | 分别分配不存在、禁用、删除、S2 所属、T2 所属角色。 | 校验拒绝，无越空间/租户授权；已有无效引用也不回退 viewer。 |
| TC02-07 / P0 / A02-2 | M 使用 Rview，目录无额外规则；调用查看与上传接口。 | 查看成功、上传拒绝且无文件/用量副作用；再授予 D upload，只有合法规则范围内上传成功。 |
| TC02-08 / P0 / A02-3 | Rempty 且无 ACL；分别调用两个 checkPermission 重载，min 为 null 和普通等级。 | level<0 在所有组合下拒绝；null 不表示无权限也可通过。 |
| TC02-09 / P0 / R02-3 | 有效 Rempty 叠加 D 的合法 view/upload 规则；随后使角色失效但保留同样 ACL。 | 有效空角色允许既有并集语义；失效角色直接拒绝，不能被 all/member ACL 重新放行。 |
| TC02-10 / P0 / A02-4 | 请求实例 A 预热权限结果；实例 B 修改角色权限或成员角色并提交；在 A 再访问/搜索。 | 下一次授权与搜索输出前 fresh 校验使用新值；不依赖展示缓存失效成功。 |
| TC02-11 / P0 / A02-5 | 创建链接后分别禁用/删除角色、使链接过期/撤销，再接受；单独运行每个变体。 | 接受时重新校验并拒绝，不增加成员，不复活角色。 |
| TC02-12 / P0 / R02-6 | 角色分别被现有成员、未过期有效邀请引用时删除。 | 删除拒绝并保留原角色/引用；只有过期或撤销邀请且无成员引用时允许删除。 |
| TC02-13 / P0 / R02-6 | 引用新增（邀请/接受/角色切换）与角色删除在空间锁前用屏障并发，两种锁顺序各运行。 | 先引用则删除拒绝；先删除则引用拒绝；最终无指向已删除角色的新有效引用。 |
| TC02-14 / P0 / R02-7 | 通过成员更新取消 O 管理身份；尝试删除/以自定义方式修改预设角色；跨空间修改角色。 | 所有者及预设保护生效，跨空间请求拒绝，原数据不变。 |
| TC02-15 / P0 / R02-7 | E 用自定义角色正常访问后，分别到期、关闭外部协作、移除成员。 | 后续查看/上传/搜索拒绝；Long 类型迁移不能绕过有效期和成员限制。 |
| TC02-16 / P0 / R02-1 | 分别为 R、R2 创建角色 ACL，仅 M 使用 R；访问各 ACL 目录。 | 仅匹配完整字符串/Long 的相同角色；两个相邻大 ID 不因精度损失混用；等级字段仍按小整数语义处理。 |
| TC02-17 / P1 / A02-6 | UI 打开直接邀请、链接创建和成员角色修改；加载预设与自定义角色；保存后再次打开。 | 选项去重、名称准确、选择保持；未知/删除引用显示“角色已失效”，不标作查看者。 |
| TC02-18 / P1 / A02-6 | 选中 R 后令提交返回权限错误/网络失败；随后恢复。 | 不显示虚假成功，不把原成员改成新角色；保留选择和明确失败状态，可重新提交。 |
| TC02-19 / P1 / A02-6 | 两个自定义角色名称相同、ID 不同，混合预设角色显示并编辑 ACL。 | 稳定显示和准确选择；保存后依据 ID 而非名称/数组下标定位，不数值相减排序造成误选。 |
| TC02-20 / P0 / R02-5 | 角色/ACL 更新事务写入后回滚；另一请求在提交前后访问。 | 未提交修改不造成权限泄漏；回滚保留原授权；缓存清理不能令旧权限在成功提交后继续授权。 |
| TC02-21 / P0 / A02-3 | 对成员、外部成员、目录接口、文件查看/上传、团队搜索分别使用同一失效角色。 | 所有授权入口一致拒绝，不能只修一个入口；搜索不得返回失权节点详情。 |
