# CR-04 同步与历次 Review 回归测试用例

来源：[需求](../20260924-code-review-design/CR-04/requirement.md)、[设计](../20260924-code-review-design/CR-04/design.md)、[第二轮修复](../20260924-code-review-design/CR-04/review-fix-2.md)、[第三轮修复](../20260924-code-review-design/CR-04/review-fix-3.md)。全部 NOT RUN。

## 夹具和观察点

- 云端根 A=`/A`、B=`/B`，对应独立本地目录与 SQLite rootId。根外 `/Outside`；排除路径 `/excluded`。文件节点 N、不同节点 X，内容 V0/V1/V2/V3 使用独立已知字节和 MD5。既测不同大小，也测同大小不同哈希。
- 默认 keep_both，除指定场景外本地有可信节点 ID、旧 MD5、旧 localMtime。目录 D 含两层子目录、空目录、排除子目录和 101 个文件以覆盖分页。每个测试预设 cursor=`100`，页末=`102`，失败前后比较精确字符串。
- 服务端层检查真实 delta 投影；引擎层可使用受控 API/文件系统；集成层使用独立真实目录和 SQLite。每轮保留状态继续，重启场景重新加载同一数据库/恢复清单。
- 安全断言：没有未经授权的云端 delete/upload，没有丢失原始字节；恢复副本须按哈希逐个可还原，不只检查文件存在。任何网络/元数据故障不得被解释为空成功页或已删除。

## 结果判定补充

TC04-28、TC04-30 等用例直接承接幂等和内容保护要求，不以当前实现的限制替代预期。若后续执行发现重复副本或删除竞态，应记录实际结果及缺陷，不预先标记通过。本轮仅编写，不推断这些用例已经满足。
