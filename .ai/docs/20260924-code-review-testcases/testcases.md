## 通用前置数据与方法

1. 后续仅在隔离测试环境使用合成用户/文件。租户 T1/T2；T1 用户 U1、同租户无关用户 U2，T2 用户 U3；T1 团队 S1/S2。各用例独立重置数据，不依赖上一条成功。
2. ID 固定使用字符串 `9007199254740993`、`9007199254740995`、`9223372036854775806`；它们均在 Java Long 范围内，前两者超过 JS 安全整数边界。不得先以 JS 数字创建夹具再转字符串。预设角色使用字符串 `0`、`1`、`2`，旧客户端兼容请求另用数值 0/1/2。
3. 并发以闩锁/屏障、事务提交点、受控存储流实现确定性调度，不以 sleep 猜时序。每个并发参与者使用独立数据库连接/事务；跨实例使用同一测试数据库与所需共享依赖。H2 结果不能替代 MySQL 锁与迁移验证。
4. 同步使用独立根 A/B、可枚举的文件内容/哈希、独立 SQLite、恢复目录和受控网络。记录每轮 cursor、sync_state、文件树、文件哈希、恢复清单、上传/删除请求及源/目标节点 ID。不得只断言函数返回。
5. 安全拒绝路径同时检查 HTTP/业务拒绝、未建立授权上下文、未产生业务副作用。文件副作用包括节点、对象引用、配额、事件与活动记录；下载包括响应首字节、输出流调用和计数；同步包括原文件、恢复副本和云端写请求。
6. 外部故障按阶段注入：读取前、读流中、权限变更提交前后、Redis CAS 前后、文件复制/校验后、状态落库前后。失败恢复用例必须保留上一轮实际状态继续，禁止重建干净引擎掩盖缺陷。
7. 通用清理：后续执行结束仅清理该用例创建的测试数据/对象/目录、关闭流/连接并解除故障注入；失败现场先保留证据。禁止自动删除真实用户数据或生产资源。
