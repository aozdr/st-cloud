# CR-03 团队复制权限测试用例

来源：[需求](../20260924-code-review-design/CR-03/requirement.md)、[设计](../20260924-code-review-design/CR-03/design.md)。全部 NOT RUN。S1 内源文件 F1/F2、含两层子目录的目录 D、目标目录 T；复制前记录节点、对象引用、空间用量、事件/活动计数。所有拒绝场景都比较这些副作用快照。建议 Controller 鉴权和服务事务集成。

| ID / 优先级 / 映射 | 前置条件与步骤 | 预期结果与证据 |
|---|---|---|
| TC03-01 / P0 / A03-1 | M 对 F1 有 view，对 T 只有 view 无 upload；直接调用复制 API。 | TEAM_PERMISSION_DENIED；节点、引用、用量、成功事件和活动均不增加。 |
| TC03-02 / P0 / A03-2 | F1 有 view 无 download，T 有 upload；复制 F1。 | 复制成功，不额外索要源 download；新增节点和对象引用/容量符合原复制语义。 |
| TC03-03 / P0 / A03-2 | 目标根分别用既有 null/0 语义，分别授予/撤销根 upload。 | 根目录与普通目录保持相同授权要求；拒绝时无写副作用。 |
| TC03-04 / P0 / A03-3 | 批量 [F1,F2]，只允许查看 F1，目标可上传；交换源顺序再运行。 | 两种顺序均整体拒绝，不发生前半批已复制或成功事件。 |
| TC03-05 / P0 / R03-2 | 源/目标分别替换为他空间节点、回收站节点、未完成上传节点；目标另用普通文件。 | 按既有归属/状态/目录约束拒绝，权限通过不能掩盖无效目标；无跨空间写入。 |
| TC03-06 / P0 / R03-2 | 目标 upload 已授予但配额不足；分别复制文件和目录。 | 配额拒绝且无部分节点/引用/用量残留，失败不发布成功复制事件。 |
| TC03-07 / P0 / A03-4 | 授权完整，分别复制单文件、批量、目录；制造同名目标。 | 命名冲突策略沿用现有规则，子树完整；引用/用量只按成功内容变化，搜索索引和同步事件与新节点一致。 |
| TC03-08 / P0 / R03-4 | 绕过隐藏按钮手工请求；在打开复制对话框后撤销目标 upload 并提交，再提交。 | 服务端按提交后的有效权限拒绝，不能依赖旧 UI 能力状态。 |
| TC03-09 / P0 / R03-1 | 分别用预设、有效自定义角色、有效空角色加目录 ACL、失效角色执行复制。 | 前三者依最终源 view/目标 upload 判定；失效角色无论 ACL 如何均不得越权，拒绝路径无副作用。 |
