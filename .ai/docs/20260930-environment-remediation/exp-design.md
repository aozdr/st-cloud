## 分析

设计约束对全部现有页面生效：不增加页面、不改导航，任意已登录页面均沿用现有权限、配额、主题和折叠状态。以下矩阵列出当前改动的全部界面触点和认证状态。它定义后续可验收行为，不能代替真实执行证据。

| 界面/状态 | 可验收行为 | 风险与观察点 |
| --- | --- | --- |
| 任意页面中的 Sidebar | 两侧租户可见性/权限均保留；配额更新不依赖重启；主题与折叠状态保持，现有入口和导航目的地不改变。 | 合并不能仅保留视觉一侧而丢失权限、配额监听，亦不能出现重复订阅。 |
| 已登录且 access 有效 | 现有页面请求和长期同步正常，无额外跳转或刷新提示。 | 成对令牌持久化须保持原有登录恢复流程。 |
| access 过期、refresh 有效 | 刷新对用户透明，请求等待同一刷新结果，再使用新 access 重放。连续第二次刷新必须使用第一轮的新 refresh。 | 多个 401 不能产生多个轮换或误登出；重放须有终止条件。 |
| 刷新成功 | 主进程、渲染进程和持久存储获得同一对令牌；页面、选中项与同步上下文继续。 | 仅更新 access 会导致下一轮认证失败；IPC 不应暴露给页面展示或日志。 |
| 真正失效/明确拒绝的 refresh | 终止重试并进入现有登录流程；并发失败共享同一终态，不能反复跳转。 | 应依服务明确失效响应处理，不能把暂时离线推断成永久失效。 |
| 网络断开、超时或服务暂时不可用 | 请求按既有错误路径结束，不无限刷新；保留仍可恢复的会话，恢复网络后允许后续正常尝试。 | 这是“真正失效时回登录”的直接验收约束；若现有实现不区分暂时失败，须在实施时修复。 |
| 应用重启/持久恢复 | 从已保存的最新令牌对恢复；不会继续使用轮换前的 refresh。 | 受控 IPC 单测不足以证明磁盘恢复，应覆盖真实持久存储适配层。 |
| 刷新中退出 | 退出状态为最终状态，旧结果不得重新登录、落盘或启动同步。 | Promise 结束与 IPC 到达顺序不可依赖。 |
| 刷新中换服 | 新服务器的地址和认证上下文保留；旧服务器返回不能写入新会话。 | 服务地址应参与会话隔离，避免跨服务器令牌使用。 |
| 刷新中新登录 | 新登录的令牌对为最终值；旧结果不能覆盖或登出新会话。 | 会话代次对失败与成功路径都须生效。 |
| 未登录/登录页面 | 沿用现有登录流程，兼容旧 IPC 调用，不新增导航入口或协议要求。 | 新 IPC 不应使旧调用成为无响应状态。 |
| 分享正常图片/缩略图 | 名称和可访问名称、焦点、选中态保持；Enter/Space 按原有行为触发，方向键按原有行为移动。 | 不能用图片替代名称或把错误提示变成额外键盘陷阱。 |
| 分享图片失败/降级 | 错误后仍可读名称、识别选中并进行上述键盘操作；焦点和对比度满足原有专项约束。 | 降级元素必须保留交互语义；需要实际键盘与颜色验证。 |
| 分享 updatedAt 更新/重新加载 | 更新后允许重试；先前图片的晚到 error 不能覆盖已更新或已成功加载的图片。 | 必须按当前图片身份/修订隔离事件，不能只看共享 error 标志。 |
