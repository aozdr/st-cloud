# PikPak 风格 UI/UX 重做 - 需求文档

> 经需求发现（PikPak 设计拆解）+ Grill Me 拷打 + 用户确认"完全采用 PikPak 风"后输出

## 1. 背景与目标

当前星云盘前端为 MEGA-红 Swiss/grid 浅色优先风格。用户要求参考 PikPak 完全重做 UI/UX，转型为深色优先、紫蓝强调、媒体流式的现代云盘视觉。

客观目标：全站视觉从"文件管理工具"转型为"媒体云盘"，保留全部文件管理功能完整性。

## 2. Grill Me 拷打结论（边界决策）

| 问题 | 决策 | 理由 |
|------|------|------|
| 非媒体文件（文档/压缩包）如何呈现？ | 统一文件类型视觉（类型色块+图标），非海报式 | 海报卡对无缩略图文件效果差，需统一视觉语言 |
| 深色为唯一还是保留浅色切换？ | 深色为默认，保留浅色切换 | 已投入明暗模式架构，保留灵活性 |
| 多主题保留还是只留紫蓝？ | 紫蓝为默认，保留多主题架构 | 已投入 6 色主题，保留切换能力 |
| 媒体分类导航位置？ | 提升到侧边栏一级 | PikPak 媒体优先 IA |
| 文件管理功能是否受影响？ | 不受影响，仅视觉重做 | 保留移动/分享/回收站/团队/权限全部功能 |

## 3. 功能范围

### 3.1 视觉系统重做（全站）
- 深色优先：dark 为默认模式
- 紫蓝强调：violet 为默认主题
- 大圆角媒体感：组件圆角适度增大
- 去暖色硬编码：移除 #0c0a09 / #1c1917 等暖石色硬编码

### 3.2 分三阶段交付
- **阶段1 设计系统基座**：token/主题/布局/导航/基础组件/空状态
- **阶段2 核心文件页**：FileGrid 海报卡/FileTable/Preview 沉浸/首页/上传
- **阶段3 次要页**：分享/团队/管理/回收站/搜索/传输管理适配

### 3.3 保留不变
- 全部文件管理功能逻辑
- 多主题切换架构
- 明暗模式切换
- 路由结构
- 状态管理

## 4. 验收标准
- 默认深色 + 紫蓝主题，视觉接近 PikPak 媒体云盘感
- 全站无暖石色硬编码残留
- 浅色模式仍可用且一致
- 编译通过（npm run build）
- 文件管理功能不受影响
