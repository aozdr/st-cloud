# 需求发现报告：星云盘团队空间功能调研与迭代需求

> **调研动机**：用户反馈团队空间功能薄弱，要求系统调研现状并参考竞品提出迭代需求。
> **调研方法**：代码层盘点后端 `st-team` 模块 + 前端 `TeamPage`/`TeamSpacePage` + 数据库表结构；竞品横向对比基于飞书云文档、钉钉钉盘、坚果云团队版、Google Drive 共享云端硬盘、OneDrive/SharePoint、百度网盘团队版的公开功能特性。
> **重要声明**：本报告为需求发现产出，记录观察事实与差距，**不替代 PM/UI 设计师做最终设计决策**。是否采用、如何落地由后续立项评审决定。

---

## 1. 调研背景与范围

### 1.1 调研对象
星云盘团队空间模块（`st-team` 后端 + `st-web` 前端 `TeamPage` / `TeamSpacePage`），对标主流团队协作型网盘/文档平台。

### 1.2 调研范围
- 团队空间生命周期管理（创建、配置、归档、删除、移交）
- 成员管理与邀请机制
- 权限模型（空间级 / 文件夹级 / 文件级）
- 协作能力（评论、@提及、活动日志、文件锁定、通知）
- 空间发现与组织（搜索、分类、排序）
- 安全审计与外部协作

### 1.3 调研边界
本次为功能层调研，不含 UI 视觉重设计（UI 设计在后续 REQ_ANALYSIS 阶段由 UI 设计师产出）。竞品功能以各产品公开文档与通用产品认知为依据，落地前需逐项验证最新版本特性。

## 2. 星云盘团队空间现状盘点

### 2.1 后端 API（`st-team` 模块，`TeamController`）

| 分类 | 接口 | 方法 | 权限要求 |
|------|------|------|----------|
| 空间管理 | 创建空间 | `POST /api/team/space` | `team:create` |
| | 我的空间列表 | `GET /api/team/spaces` | 已认证 |
| | 空间详情 | `GET /api/team/{spaceId}` | 查看者+ |
| | 修改空间 | `PUT /api/team/{spaceId}` | 管理员 |
| | 删除空间 | `DELETE /api/team/{spaceId}` | 管理员 |
| 成员管理 | 邀请成员 | `POST /api/team/{spaceId}/member` | `team:invite` |
| | 成员列表 | `GET /api/team/{spaceId}/members` | 查看者+ |
| | 修改成员角色 | `PUT /api/team/{spaceId}/member/{memberId}` | 管理员 |
| | 移除成员 | `DELETE /api/team/{spaceId}/member/{memberId}` | 管理员 |
| 文件操作 | 空间文件列表 | `GET /api/team/{spaceId}/files` | 查看者+ |
| | 路径解析 | `GET /api/team/{spaceId}/files/by-path` | 查看者+ |
| | 文件详情 | `GET /api/team/{spaceId}/files/{nodeId}` | 查看者+ |
| | 文件夹树 | `GET /api/team/{spaceId}/tree` | 查看者+ |
| | 创建文件夹 | `POST /api/team/{spaceId}/folder` | 编辑者+ |
| | 删除至回收站 | `POST /api/team/{spaceId}/files/delete` | 编辑者+ |
| | 重命名 | `PUT /api/team/{spaceId}/files/{nodeId}/rename` | 编辑者+ |
| | 移动 | `POST /api/team/{spaceId}/files/move` | 编辑者+ |
| | 复制 | `POST /api/team/{spaceId}/files/copy` | 查看者+ |

### 2.2 数据模型

**`team_space` 表**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 空间ID |
| tenant_id | BIGINT | 租户ID |
| space_name | VARCHAR(100) | 空间名称 |
| description | VARCHAR(500) | 空间描述 |
| icon | VARCHAR(500) | 空间图标 |
| owner_id | BIGINT | 创建者ID |
| storage_used | BIGINT | 已用存储 |
| storage_quota | BIGINT | 存储配额，NULL=不限 |
| status | TINYINT | 0-禁用 1-正常 |
| created_at / updated_at / deleted | - | 基础字段 |

**`team_member` 表**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 成员记录ID |
| tenant_id | BIGINT | 租户ID |
| space_id | BIGINT | 空间ID |
| user_id | BIGINT | 用户ID |
| role | TINYINT | 0-管理员 1-编辑者 2-查看者 |
| joined_at | DATETIME | 加入时间 |
| last_active_at | DATETIME | 最后活跃时间（**字段存在但代码从未更新**） |

### 2.3 权限模型

三级角色，空间级单一权限粒度：

| 角色 | 值 | 权限 |
|------|----|------|
| 管理员 | 0 | 全部操作（增删改空间配置、管理成员、文件操作） |
| 编辑者 | 1 | 文件增删改、创建文件夹、移动、删除 |
| 查看者 | 2 | 浏览文件、复制 |

权限校验逻辑（`checkPermission`）：查 `team_member` 表，比较 `role <= minRole`，无记录则拒绝。**无文件夹级/文件级权限，无自定义角色，无操作级细粒度控制。**

### 2.4 前端页面

**`TeamPage.tsx`（空间列表页）**：
- 空间卡片网格（名称、描述、成员数、存储进度条）
- 创建空间弹窗（仅名称 + 描述）
- 点击卡片进入空间详情

**`TeamSpacePage.tsx`（空间详情页）**：
- 复用 `FileBrowser` 组件浏览空间文件
- 上传按钮（调用 `useUpload`）
- 成员管理弹窗：按用户名邀请 + 角色选择 + 移除成员
- 设置弹窗：**仅存储配额调整**（名称/描述/图标编辑入口缺失）

### 2.5 现状核心问题总结

| 问题域 | 具体问题 |
|--------|----------|
| 邀请机制 | 仅支持按用户名直接添加，无邀请链接、无邮件邀请、无审批流程、无批量邀请 |
| 权限模型 | 仅空间级三级角色，无文件夹/文件级权限，无自定义角色，无操作级控制（如"可下载不可删除"） |
| 成员管理 | 无法退出空间、无法移交所有权、`last_active_at` 形同虚设、无分组/部门概念、无批量操作 |
| 协作能力 | 无文件评论、无@提及、无活动日志、无文件锁定、无操作通知 |
| 空间管理 | 设置仅能改配额，名称/描述/图标无法编辑；无空间归档、无模板、无子空间 |
| 空间发现 | 无搜索、无排序选项、无分类/标签、无收藏/置顶 |
| 安全审计 | 仅全局审计日志（`AuditAspect`），无空间级活动流、无成员操作可见性 |
| 通知体系 | 完全缺失，成员变动/文件变更无任何提醒 |

## 5. 迭代需求设计

基于差距分析与实现复杂度，将迭代分为三个阶段：P0（基础协作补齐）→ P1（协作增强）→ P2（高级协作）。

### 5.1 迭代路线总览

| 阶段 | 主题 | 核心目标 | 涉及模块 |
|------|------|----------|----------|
| **P0** | 基础协作补齐 | 让团队空间"可用"：邀请链接、空间设置完善、活动日志、成员退出/移交 | st-team, st-web |
| **P1** | 协作增强 | 让团队空间"好用"：文件夹权限、文件评论、@提及通知、空间搜索 | st-team, st-core, st-web |
| **P2** | 高级协作 | 让团队空间"专业"：文件锁定、自定义角色、外部协作者、空间统计 | st-team, st-share, st-web |

---

### 5.2 P0：基础协作补齐（建议优先实施）

#### 需求 P0-1：邀请链接机制

**用户故事**：作为空间管理员，我希望生成邀请链接分享给同事，他们点击即可申请加入空间，而无需逐个输入用户名。

**验收标准**：
- 管理员可生成空间邀请链接，支持设置有效期（24h / 7d / 永久）与默认角色
- 被邀请人点击链接后，若已登录则直接加入空间（或需管理员审批），若未登录则引导登录后加入
- 邀请链接可随时撤销/失效
- 支持查看已生成的邀请链接列表及使用状态
- 新增数据表 `team_invite`（invite_code, space_id, role, expire_at, created_by, status, used_by, used_at）

#### 需求 P0-2：空间设置完善

**用户故事**：作为空间管理员，我希望能编辑空间名称、描述和图标，而不仅仅是调整存储配额。

**验收标准**：
- 设置弹窗支持编辑空间名称、描述、图标（emoji 选择器或 URL）
- 存储配额调整保留
- 修改空间名称后，列表页与详情页同步更新
- 复用现有 `PUT /api/team/{spaceId}` 接口（已支持字段更新，前端补全表单即可）

#### 需求 P0-3：空间活动日志

**用户故事**：作为空间成员，我希望看到空间内最近发生了什么操作（谁上传/删除/邀请了谁），以便了解团队动态。

**验收标准**：
- 空间详情页新增"动态"Tab，展示空间内操作时间线
- 记录操作类型：文件上传/删除/重命名/移动、成员加入/退出/角色变更、空间设置修改
- 每条记录包含：操作人、操作类型、目标对象、时间戳
- 支持按操作类型筛选
- 活动日志仅空间成员可见，查看者可读
- 可复用/扩展现有 `AuditLog` 机制按 spaceId 过滤，或新增 `team_activity` 表

#### 需求 P0-4：成员退出与所有权移交

**用户故事**：作为普通成员，我希望可以主动退出不需要的空间；作为空间拥有者，我希望可以将空间移交给他人后安心离开。

**验收标准**：
- 非管理员成员可主动退出空间（`POST /api/team/{spaceId}/leave`）
- 管理员退出前须先移交所有权或将其他成员提升为管理员
- 空间拥有者可将所有权移交给另一名管理员（`POST /api/team/{spaceId}/transfer`），移交后自己降为管理员
- 退出空间后文件归属不变（文件属于空间而非个人），退出成员失去访问权
- 最后一名管理员退出时阻止操作并提示

#### 需求 P0-5：成员活跃追踪

**用户故事**：作为管理员，我希望看到成员最后活跃时间，以识别不活跃成员进行清理。

**验收标准**：
- 成员访问空间（浏览文件、操作文件）时更新 `last_active_at`
- 成员列表展示最后活跃时间
- 支持按活跃时间排序

---

### 5.3 P1：协作增强

#### 需求 P1-1：文件夹级权限

**用户故事**：作为空间管理员，我希望能对特定文件夹设置不同的访问权限，例如让某成员只能查看"财务"文件夹但可编辑"项目"文件夹。

**验收标准**：
- 支持对文件夹设置成员级或角色级权限覆盖（查看/编辑/管理/无权限）
- 权限向下继承，子文件夹默认继承父文件夹权限，可显式中断继承
- 文件浏览时根据权限控制操作按钮显隐
- 新增数据表 `team_folder_permission`（folder_node_id, space_id, subject_type[role/member], subject_id, permission）
- `checkPermission` 扩展为支持按 nodeId 校验文件夹级权限

#### 需求 P1-2：文件评论与@提及

**用户故事**：作为空间成员，我希望能在文件上发表评论并@同事，让协作沟通与文件关联而非散落在聊天工具中。

**验收标准**：
- 文件详情/预览侧边栏支持发表评论
- 评论支持@提及空间内成员，被@成员收到站内通知
- 评论支持回复（二级嵌套）
- 评论可编辑/删除（本人或管理员）
- 新增数据表 `team_comment`（id, space_id, node_id, user_id, content, parent_id, mentions, created_at）
- 通知通过站内消息中心推送

#### 需求 P1-3：站内通知体系

**用户故事**：作为空间成员，当有人@我、邀请我加入空间、或我关注的文件发生变更时，我希望收到通知。

**验收标准**：
- 新增站内通知中心（顶部铃铛图标 + 通知列表页）
- 通知类型：邀请通知、@提及、文件变更（关注文件被修改/删除）、成员变动
- 通知支持已读/未读标记，支持批量已读
- 新增数据表 `notification`（id, user_id, type, title, content, ref_type, ref_id, read, created_at）
- 预留邮件/WebHook 通知扩展点

#### 需求 P1-4：空间搜索与排序

**用户故事**：作为用户，当我有多个团队空间时，我希望能搜索和排序以便快速找到目标空间。

**验收标准**：
- 空间列表页支持按名称搜索
- 支持按创建时间、成员数、存储用量排序
- 支持置顶/收藏常用空间
- 新增 `team_member.is_pinned` 字段或用户级偏好表

---

### 5.4 P2：高级协作

#### 需求 P2-1：文件锁定

**用户故事**：作为编辑者，当我在编辑一个重要文件时，我希望锁定它防止他人同时修改导致冲突。

**验收标准**：
- 编辑者可锁定文件/文件夹，锁定后其他人无法修改/删除/重命名
- 锁定显示锁定人与锁定时间
- 锁定人可解锁，管理员可强制解锁
- 锁定自动过期（默认24h，可配置）
- 新增 `file_node.locked_by` / `file_node.locked_at` / `file_node.lock_expire_at` 字段

#### 需求 P2-2：自定义角色

**用户故事**：作为管理员，我希望自定义角色并精细控制每个角色的权限组合，而非只能用预设的三个角色。

**验收标准**：
- 管理员可创建自定义角色，勾选权限项（查看/上传/下载/删除/重命名/移动/分享/管理成员/管理设置）
- 角色可编辑/删除（已使用角色不可删，可停用）
- 新增数据表 `team_role`（id, space_id, name, permissions_json, is_default）
- `team_member.role` 扩展支持引用自定义角色

#### 需求 P2-3：外部协作者

**用户故事**：作为管理员，我希望能邀请外部合作伙伴加入特定空间协作，同时控制其权限范围。

**验收标准**：
- 支持将非本租户用户标记为外部协作者
- 外部协作者仅可见被邀请的空间，不可见组织内其他空间
- 外部协作者可设置访问有效期，到期自动移除
- 管理员可全局开关"是否允许外部协作者"
- `team_member` 新增 `member_type`（0-内部 1-外部）与 `expire_at` 字段

#### 需求 P2-4：空间统计仪表板

**用户故事**：作为管理员，我希望看到空间的存储用量、文件数量、成员活跃度等统计数据，以便管理空间资源。

**验收标准**：
- 空间设置页新增统计 Tab
- 展示：存储用量趋势、文件总数、各类型文件占比、成员活跃度排行、近期操作统计
- 支持按时间范围筛选（7天/30天/90天）
- 图表使用 Recharts 渲染

## 6. 风险与依赖

| 风险/依赖 | 说明 | 影响 | 缓解措施 |
|-----------|------|------|----------|
| 文件夹级权限性能 | 每次文件操作需递归校验权限链 | 中 | 缓存权限树，预计算有效权限 |
| 活动日志写入量 | 高频操作产生大量日志 | 中 | 异步写入，定期归档，分区表 |
| 通知实时性 | 站内通知需实时推送 | 中 | WebSocket / SSE 推送，或轮询降级 |
| 权限模型迁移 | 从三级角色到自定义角色需数据迁移 | 高 | P2 阶段做，保留兼容层，渐进迁移 |
| 现有 FileService 耦合 | 团队文件操作委托 FileService，权限扩展需侵入 | 高 | P1 文件夹权限阶段需重构 `checkPermission` 签名 |
| 协同编辑复杂度 | 实时协同编辑需 OT/CRDT 引擎 | 高 | 暂不纳入三期迭代，后续单独评估 |
