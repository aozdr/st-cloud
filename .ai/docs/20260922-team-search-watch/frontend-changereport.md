# 团队搜索与通知前端变更报告

任务：`TASK-20260922-team-search-watch-frontend`  
修订：`tsw-code-r2`  
执行：GPT-5.6 Terra high

## 当前前端能力

- `SearchPage` 按 URL 的 `scope` 在个人搜索与团队搜索之间切换。团队搜索使用 `/search/team`，保留个人搜索原有请求与结果契约。
- 团队模式加载可访问空间，选择空间后可按关键词、类型、大小、日期检索；目录范围先经 `teamFileSource` 读取并由服务端核权，再发起搜索。
- 团队结果使用游标加载更多，取消过期请求并通过请求序号避免旧响应覆盖新查询；结果打开时生成团队空间内的受控路由。
- 已有 `NotificationBell` 使用通知列表、未读计数、Escape 关闭和服务端 target 接口实时核权；新关注通知只有在 target 可用时才跳转。

## 本次修改

- 团队搜索的文件类型筛选条在窄屏改为整行可横向滚动。每个按钮和图标设为不可压缩，标签保持单行，避免 375px 下中文逐字竖排及“压缩包”溢出。
- 文件类型筛选容器补充语义分组标签；按钮仍是原生可聚焦控件。键盘 Tab 可逐项到达，浏览器会把获得焦点的横向溢出按钮滚动到可见区域。
- 将 `NotificationBell` 接入 `TopBar` 的全局操作区。`TopBar` 同时用于桌面与移动布局，通知入口因而在两端都可打开。
- `NotificationBell` 在小于 `sm` 的视口中改为相对视口左右各保留 12px，并用铃按钮实际底边计算弹层顶部及可用高度；因此 375px 时不会因铃按钮位于顶栏中间而向左越出视口。桌面仍使用 `absolute right-0` 锚定铃按钮。
- 通知列表新增明确的加载、请求失败和重试状态。列表请求失败时不再显示“暂无通知”，避免把服务异常伪装成空数据。

## 边界

- 未改动搜索、通知、关注接口、请求参数或权限判断。
- 未修改后端、数据库、路由或业务数据。
