# CR-07 缩略图格式及资源保护：需求

修订：design-v1；P1；仅需求与设计。

## 现状与目标

PreviewServiceImpl 的 IMAGE_TYPES、ShareServiceImpl 的 SHARE_IMAGE_TYPES 包含 webp/svg，生成路径直接 ImageIO.read 整幅解码。PreviewModal 普通图片请求缩略图，分享胶卷也请求服务端缩略图，无明确失败图标状态。

目标：浏览器可显示图片与服务器可生成 JPEG 缩略图的能力分开；不支持或超过资源上限时可预测降级，不能先分配完整大像素矩阵后才检查大小。

## 用户、范围与规则

用户在个人/团队文件、历史版本和分享中查看图片或胶卷导航。只修改这几条缩略图路径和相应显示；不引入图像处理服务、大型解码依赖或视频转码。

- R07-1：服务端缩略图允许 jpg/jpeg/png/gif/bmp，并再次校验实际 reader 能力；WebP/SVG 不进入服务端 JPEG 生成。文件类型分类仍可认作图片，不把全局 isImage 收窄。
- R07-2：WebP/SVG 主图通过已有授权原文件预览路径显示，SVG 只以 img 显示，不注入 HTML、不作为 iframe/document 执行。浏览器不支持则显示明确降级。
- R07-3：限制源文件字节数、图片宽高像素乘积和同时解码数量；像素检查在完整解码之前。元数据缺失/损坏、读入超限、无 reader 均不得冒险解码。
- R07-4：胶卷遇到不支持、超限或失败显示通用图片图标，保留文件名、选择与导航能力；不能为了 fallback 自动拉取所有大原图。
- R07-5：普通预览、历史版本、匿名分享使用同一资源限制和格式白名单，避免第二条未防护路径。
- R07-6：分享缩略图始终不计次且不返回原文件内容；点击主图走原流及 CR-05 计次，保留提取码、下载开关和范围校验。
- R07-7：同图首次并发请求允许跨实例少量重复生成，但单实例解码并发有上限；超出处理能力时快速返回可降级结果，不无界排队。

## 验收标准

A07-1：常规 jpg/png 和受支持格式正常缩略图。A07-2：WebP/SVG 不触发 ImageIO 整图解码，主图与导航有合理显示。A07-3：超字节或超像素图片在完整解码前停止，普通/版本/分享一致。A07-4：坏文件和并发高压不产生无界内存分配，资源被关闭。A07-5：权限与分享次数语义未被 fallback 绕过。

## 契约与风险

无 DB schema 变化。缩略图 URL 接口保持 Result<String>；用现有业务错误响应表达不可生成，前端显式降级。源文件预览仅走原已授权路径，不把“缩略图失败”自动当成取得下载权限。资源阈值是可配置保守默认，需未来运行验证，不能宣称绝无 OOM。无未决范围决策。
