## 统一数据迁移设计

本轮不创建 SQL。后续实施 CR-01/02 时按执行时目录最大编号新增两个递增 SQL（当前已看到编号至 43，不能在未来未经核对就固定复用 44/45）。每文件首行 `SET NAMES utf8mb4;`，分别扩展 sys_user.security_version 与 team_member/team_invite.role。历史 init 文件不作为存量数据库升级替代。

同步 `st-core/src/test/resources/schema.sql` 及实际声明相关表的其他模块测试 schema；未来执行 H2 与 SchemaConsistencyTest，再运行 `.ai/scripts/compare-schema.ps1` 记录迁移前差异，在已获授权的开发/测试库迁移并登记 `schema_version`，唯一版本为执行日期 YYYYMMDD.N，含主题、SQL 清单、执行人、备注，最后再次对比要求退出码 0。生产库必须另有明确部署授权。

新增版本列不回填为非零强制所有用户变更；旧 Token 由缺少 claim 拒绝。角色扩容保持预设原值，不猜测修正既有非法角色。迁移先检查实际列定义、行数与引用异常，确定 DDL 锁影响；不可假定所有版本 ALTER 都在线无锁。回退保留宽字段/新列，不执行破坏性降级。

## 模块集成与发布

建议未来实施顺序 CR-03→05→01→02→04→06→07，与测试阶段串行集成。代码实现前先完成测试用例及相应编码 TASK；本目录设计 TASK 不是编码授权。

- CR-01 完整切换鉴权实例后要求重登；混合旧实例不具备撤权保证。
- CR-02 先兼容前端读取，再后端字符串类型与角色选择开放；旧桌面内嵌前端需要升级。
- CR-04 新客户端与服务端能力标记配套；恢复清单和旧 root 状态不可清空，失败保留游标。
- CR-06 共享秘密先注入，普通滚动保持相同值。
- CR-07 先具备 UI fallback，再限制缩略图能力；CR-05 计次语义不能被原图 fallback 绕过。

## 后续验证要求摘要

只规定所需证据类型，不编写测试步骤：权限撤销含并发签发/变更与 WS；角色含大 ID、无权限、跨空间、邀请和删除竞态；复制含拒绝无副作用；分享观察响应首字节及资格数；同步观察真实目录、状态、恢复清单和失败游标；搜索包含 Spring 初始化；缩略图证明 reader.read 未在超限时调用及资源关闭。

后续后端按受影响模块运行 Maven 验证，Web 构建，桌面 npm test/lint/build；加入桌面验证文件时必须更新显式测试文件列表。所有本轮运行结果均为 NOT RUN。
