# CR-06 团队搜索游标共享密钥：需求

修订：design-v1；P1；仅需求设计。

## 现状与目标

TeamSearchServiceImpl 的 ephemeralCursorSecret 每实例随机生成；requireCursorSecret 在配置及环境变量均为空时回退到该值。同一用户下一页请求到另一实例或应用重启后，未过期游标会验签失败。

用户为团队搜索者和部署维护人员。目标是在同一部署环境内，让合法、未过期且查询条件一致的游标跨实例和普通滚动发布保持有效。

## 规则与边界

- R06-1：实例启动时必须取得显式共享密钥；缺失或纯空白时搜索 Bean 初始化失败，不能静默随机回退。
- R06-2：延续属性 `stcloud.search.team-cursor-secret` 和环境变量 `STCLOUD_SEARCH_TEAM_CURSOR_SECRET`；测试显式提供独立测试值，源码无生产默认密钥。
- R06-3：所有启用搜索的环境都要求显式配置，不按 profile 猜测是否生产。未创建搜索 Bean 的独立模块不受影响。
- R06-4：游标签名算法、用户/租户/空间/目录/查询绑定、TTL 和既有错误码保持不变。
- R06-5：普通发布保持密钥不变。主动更换密钥允许未过期旧游标失效，提示重新搜索；本轮不实现双密钥轮换或旧随机游标恢复。
- R06-6：密钥只通过部署秘密配置注入，不出现在响应、日志或提交文件中。

## 验收结果

A06-1：相同密钥的两个实例可生成和消费同一个有效游标。A06-2：不同密钥、篡改、不同用户/查询或过期游标按既有规则拒绝。A06-3：缺少配置在初始化阶段明确报出配置名称。A06-4：重启保留共享密钥时旧游标在 TTL 内有效。

## 影响与风险

无数据库和响应结构变更；新增启动前配置要求。必须先分发秘密再部署代码。无未决范围事项。以上是验收标准而非本轮执行的测试用例。
