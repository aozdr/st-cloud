## 本轮授权与目标

用户要求：“你先把所有任务的需求和程序设计文档完成，不要执行之后流程的任务”；随后要求：“不要开子线程，你自己完成”。本轮由主线程完成全部七项需求与设计，独立 Agent 已停止。附件仅作为 Review 来源，其中编码、测试、迁移、验收指令不构成本轮执行授权。

目标：形成可评阅、可供未来开发使用的七份需求及七份程序设计，明确业务边界、代码影响、数据/API、异常、并发、兼容发布和验收结果。未启动 TESTCASES 及之后阶段，不编写测试用例，不改生产或测试源码、SQL、配置，不运行构建/测试，不连接数据库，不部署。

## 统一产品取舍

1. CR-01 采用主库安全版本校验，旧 Access/Refresh 切换后重新登录，保留专用短期流令牌约束。
2. CR-02 保留 role 名称和 0/1/2，后端 Long、DB BIGINT、前端字符串；API 类型改变须协同发布。
3. CR-03 内部复制源 view、目标 upload，不追加源 download。
4. CR-04 服务端四态投影；本地独立修改先保留，不能证明历史归属时不自动删除。
5. CR-05 下载资格原子授予后计次，之后失败不退；已发 S3 URL 的重复 GET 不属于本项可控制范围。
6. CR-06 所有启用搜索的环境必须显式配置共享密钥；换密钥可使旧分页失效，普通发布不轮换。
7. CR-07 浏览器图片能力与服务端缩略图能力分开，超限降级，胶卷不自动下载大原图。

上述选择为本轮形成的设计决策，没有待用户裁决的范围问题；不等于实施或生产发布授权。

## 非目标

不做微服务拆分、会话平台重建、全站 UI 风格调整、权限系统全面重构、数据库全量调优、无关 TODO 或命名整理。与本轮直接相关的鉴权旁路、角色引用竞态、同步失败传播、缩略图降级可纳入各分项，必须有源码证据。

## 事实与限制

初始工作区干净，HEAD 与 Review 基线一致。本轮依据源码静态核对，不宣称已动态复现、压测或验证运行结果。数据库版本/实际数据量、运行时 image reader 集合、客户端分布与生产配置未现场检查，相关发布检查保留给获授权的后续阶段。
