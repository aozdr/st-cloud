# 架构设计评阅材料

修订：design-v1；评阅方式：主线程自行核对；不是独立 Agent 审查，也不是实现后的 CODE_REVIEW/SECURITY_REVIEW。

## 结论

七项方案采用现有模块和权限/事件/存储契约，具备后续细化为测试及实现任务的边界。当前选择如下；没有未解决的产品范围裁决项。实现风险仍需后续运行证据，不能以本材料宣布系统整改完成。

| 议题 | 采用 | 不采用及理由 |
|---|---|---|
| Access 撤权 | 主库 securityVersion、原子安全写、快照签发 | Redis miss 回填无法单独证明撤权即时性；短 JWT 不能替代撤销 |
| RBAC 并发 | 安全管理写事务统一租户锁序，登录读一致快照 | 异步递增版本存在撤权窗口；用户集合读写交错需串行点 |
| 角色引用 | 现有 role 扩 Long/BIGINT、字符串 API | 同时重命名 role_id 或迁移所有预设会扩大无必要变更 |
| 复制 | 源 view、目标 upload | 不增加源 download，避免顺带改变复制产品语义 |
| 同步 | 根内四态投影、客户端完整消费和安全恢复 | 只改服务端过滤不能补目录子树，也不能修复吞错推进游标 |
| 分享次数 | 原子授予后发送，失败不退 | 事后计数挡不住内容输出；退款需额外幂等协议 |
| 搜索秘密 | 初始化强制配置同一密钥 | 随机回退导致跨实例必然不兼容 |
| 图片 | 最小共享渲染器、头部尺寸检查、有限临时文件/并发 | 解码后检查太晚；引入大型 WebP/SVG 处理体系超出需求 |

## 关键边界核对

1. 无数据库事务包含 S3/HTTP 或新增 Redis 网络调用。AuthService 当前注册/管理方法的 Redis 操作需在 CR-01 拆至事务外；分享原子计数先提交再输出。
2. 安全版本与权限写入同事务。角色 ID 与 legacy 权限等级区分，空权限和失效角色不被默认 viewer 掩盖。
3. download/editor 令牌是明确保留的短期用途例外，不借它们进入普通 API/WS。已鉴权在途请求不在撤权保证内。
4. 同步旧绝对路径不传给客户端作为本地路径；只在充分证据下清理受管理内容，本地独立变化有恢复副本。
5. 分享缩略图不退化为无需计数的原文件出口；预签名 URL 复用保证边界已在需求公开。
6. WebP/SVG 不因后端能力收窄从全局图片分类消失，历史版本不能误读当前原图。

## 风险及处置

- CR-01 增加认证 DB 读量与低频管理锁等待：后续相称负载验证，不引入未经一致性证明的缓存捷径。
- CR-02 旧客户端数字假设：先兼容读层/整体窗口切换；数据库只扩不缩。
- CR-04 原有本地状态缺失时无法自动认定残留：保留并提示人工核对，不宣称全部旧数据自动恢复。
- CR-05 URL 实际复用不受应用计数控制：资格计数边界写明，不误报为下载字节级次数控制。
- CR-07 header reader 和 codec 仍消耗资源：读入/像素/并发分层限制，默认参数需后续验证，不声称绝对无 OOM。
