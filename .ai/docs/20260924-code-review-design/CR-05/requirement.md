# CR-05 分享下载限额并发控制：需求

修订：design-v1；基线：912996e1；P0；需求完成，功能未实现。

## 问题、用户与目标

`ShareServiceImpl.streamShareFile` 在完整输出后才条件递增 download_count。限额为 1 时，多个匿名访问者可同时收到内容，即使最终计数未超限。`getDownloadUrl` 已在返回预签名 URL 前计数。用户是设置限额的分享者和访问分享的匿名/登录访问者。

目标：同一分享所有应用实例竞争同一数据库计数，未经额度授予的流式请求不能输出文件字节。

## 业务规则与边界

- R05-1：提取码、验证码、有效状态、过期、下载开关、权限集、文件存在/可用、上传完成、分享子树边界校验均先于额度消耗。
- R05-2：成功原子占位视为获得一次下载资格。占位后即使网络断开、读流失败或客户端未接收首字节，也不退次数；占位前失败不计数。这是明确的资格计数，不是完整文件传输成功计数。
- R05-3：download_limit 为 null 时不限制，但仍记录成功授予次数；有上限时数据库条件更新结果是唯一最终判据。
- R05-4：分享缩略图不消耗次数，并保留现有访问权限校验；原文件流预览仍消耗次数。修正前端声称“不增加下载次数”的过时注释。
- R05-5：URL 发放与流式访问共用限额，不能各自维护计数。重试按新的资格申请计数，本轮不新增会话、退款或 Range 配额协议。
- R05-6：已经发出的 S3 预签名 URL 可在有效期内复用。本轮保障应用层资格发放与流输出，不宣称限制对象存储实际 GET 总次数；改造为单次下载票据或全代理属于另一个产品范围。

## 异常与验收标准

| 编号 | 结果 |
|---|---|
| A05-1 | limit=1 时并发五个流式请求，最多一个输出文件内容，其余在输出前拒绝 |
| A05-2 | URL 发放与流请求并发，授予总数不超过剩余额度 |
| A05-3 | 非法访问及源流打开失败不消耗次数；占位后传输失败不退款 |
| A05-4 | 不限次数正常下载；缩略图不计数；现有限速和分享范围限制仍生效 |

## 影响与风险

无 schema 或接口结构变化。失败下载会消耗已授予额度，是本项明确行为变化，需要写入发布说明。数据库不可用时拒绝授予，不能 fail-open。保留既有错误码。未决产品问题：无；预签名 URL 复用是公开边界而非已解决事项。
