# CR-02 最小交互规格

修订：design-v1。沿用 TeamSpacePage、RoleManageDialog、FolderPermissionDialog 当前视觉与组件，不做布局重设计。

## 页面和流程

1. 成员管理的“搜索用户邀请”、邀请链接角色选择：预设管理员/编辑者/查看者在前，其后为启用自定义角色；值全为字符串。角色加载失败显示错误与重试，禁止在不完整列表上提交，不能静默降级成查看者。
2. 成员列表对可管理的非所有者提供角色选择与明确保存动作，调用现有 PUT `/team/{spaceId}/member/{memberId}?role=...`。保存中禁重复操作；成功刷新成员及当前用户有效权限；失败保持原角色展示和待提交选择。
3. 角色名称使用服务端角色列表映射；失效引用显示“角色已失效”，保留 ID 供管理定位，不解释成查看者。用户看到名称而非 Snowflake 运算值。
4. 创建或修改自定义角色后关闭角色对话框时刷新选项；角色被其他管理员删除时提交失败并刷新列表，不自动替换选择。
5. 所有者角色不可编辑；自定义权限对入口的可见性沿用服务端有效权限判据，不单靠 role==='0' 推断自定义角色能力。原所有者专用操作仍保持所有者校验。
6. 邀请链接详情和加入页正确显示自定义名称。角色失效时显示“邀请角色已失效，请联系管理员”，不执行加入。外部成员有效期显示和限制保持现状。
7. FolderPermissionDialog 的 role 主体选择复用字符串 ID，预设去重，自定义名称正常回显。删除被引用角色展示后端拒绝原因。

## 交互状态与可访问性

加载、可编辑、保存中、成功、失败和权限被撤销六种状态均有可见文本；按钮/选择器有可访问名称，支持键盘切换和提交，失败提示不能只用颜色。沿用现有弹窗焦点与关闭行为，不创建新的视觉规范。

## 设计自检

需求 R02-8 与全部角色输入/输出入口已映射；本轮仅文本规格，无 UI 编码或浏览器验收。自检不冒称独立体验评审。
