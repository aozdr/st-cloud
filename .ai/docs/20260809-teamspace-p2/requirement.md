# 需求评审：团队空间 P2 高级协作

> 本文档与 UI/UX 设计文档（uiSpec）同步产出，经需求评审定版后，共同作为前端实现的唯一依据。
> 关联调研文档：`.ai/docs/20260809-teamspace-iteration-discovery.md`
> 关联 P0/P1 文档：`.ai/docs/20260809-teamspace-p0/`、`.ai/docs/20260809-teamspace-p1/`

## 1. 背景

P0 补齐基础协作、P1 增强协作能力后，团队空间完成度约 60%。P2 聚焦"高级协作"，目标达到"专业"水平（约 80%+）。

当前高级协作痛点：
- **编辑冲突无防护**：多人同时编辑同一文件可能导致覆盖，无锁定机制
- **角色不可定制**：仅预设三级角色（管理员/编辑者/查看者），无法精细控制权限组合
- **无法外部协作**：无法邀请组织外合作伙伴，跨组织协作需通过分享链接间接实现
- **空间管理无数据支撑**：管理员无法查看存储用量趋势、文件分布、成员活跃度等统计

## 2. 用户故事

### P2-1 文件锁定
> 作为编辑者，当我在编辑一个重要文件时，我希望锁定它防止他人同时修改导致冲突。

### P2-2 自定义角色
> 作为管理员，我希望自定义角色并精细控制每个角色的权限组合，而非只能用预设的三个角色。

### P2-3 外部协作者
> 作为管理员，我希望能邀请外部合作伙伴加入特定空间协作，同时控制其权限范围。

### P2-4 空间统计仪表板
> 作为管理员，我希望看到空间的存储用量、文件数量、成员活跃度等统计数据，以便管理空间资源。

## 3. 功能范围

### 3.1 P2-1 文件锁定

**功能点：**

1. 编辑者以上可锁定文件/文件夹
2. 锁定后其他人无法修改/删除/重命名/移动该节点
3. 锁定信息展示：锁定人昵称 + 锁定时间 + 剩余有效时间
4. 解锁权限：锁定人本人可解锁，管理员可强制解锁
5. 锁定自动过期：默认 24 小时，可配置（1h/6h/24h/永久）
6. 文件列表中锁定文件显示锁定图标
7. 锁定/解锁操作记录到活动日志

**数据模型：**

`file_node` 表新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| locked_by | BIGINT | 锁定人ID，NULL=未锁定 |
| locked_at | DATETIME | 锁定时间 |
| lock_expire_at | DATETIME | 锁定过期时间，NULL=永久 |

### 3.2 P2-2 自定义角色

**功能点：**

1. 管理员可创建自定义角色，勾选权限项：
   - `view`（查看文件）、`upload`（上传）、`download`（下载）、`delete`（删除）
   - `rename`（重命名）、`move`（移动）、`share`（分享）、`manage_members`（管理成员）、`manage_settings`（管理设置）
2. 角色管理：创建、编辑、删除（已使用角色不可删，可停用）、停用/启用
3. 邀请成员时可选择自定义角色
4. **兼容设计**：预设三级角色（0-管理员/1-编辑者/2-查看者）保留不变，自定义角色 ID >= 100
5. `checkPermission` 扩展：当 role >= 100 时从 `team_role` 表加载权限矩阵判断

**数据模型：**

新增 `team_role` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 角色ID（>= 100） |
| tenant_id | BIGINT | 租户ID |
| space_id | BIGINT | 空间ID |
| name | VARCHAR(50) | 角色名称 |
| permissions | VARCHAR(500) | 权限JSON，如 `{"view":true,"upload":false,...}` |
| status | TINYINT | 0-停用 1-启用 |
| created_at / updated_at / deleted | - | 基础字段 |

### 3.3 P2-3 外部协作者

**功能点：**

1. 管理员可将成员标记为外部协作者（member_type=1）
2. 外部协作者可设置访问有效期（expire_at），到期自动移除
3. 外部协作者仅可见被邀请的空间，不可见组织内其他空间（现有设计天然满足：空间通过 team_member 关联）
4. 管理员可全局开关"是否允许外部协作者"
5. 成员列表区分内部/外部，外部成员显示标签和有效期
6. 定时任务清理过期外部协作者

**数据模型：**

`team_member` 新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| member_type | TINYINT | 0-内部 1-外部，默认0 |
| expire_at | DATETIME | 外部协作者有效期，NULL=永久 |

新增 `team_external_config` 表（空间级外部协作配置）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 配置ID |
| space_id | BIGINT | 空间ID |
| allow_external | TINYINT | 是否允许外部协作者：0-否 1-是 |

### 3.4 P2-4 空间统计仪表板

**功能点：**

1. 空间设置弹窗新增"统计"Tab
2. 展示指标：
   - 存储用量概览（已用/总量/占比）
   - 文件总数 & 各类型文件占比（图片/视频/文档/音频/其他）
   - 成员活跃度排行（按 last_active_at 排序，Top 5）
   - 近期操作统计（基于 team_activity，按操作类型分组计数）
3. 时间范围筛选：7天/30天/90天
4. 图表使用 Recharts 渲染（饼图 + 柱状图）

**数据模型：** 无新增表，基于现有 `file_node`、`team_member`、`team_activity` 聚合查询

## 4. 影响模块

| 层 | 模块 | 影响说明 |
|----|------|----------|
| 后端 | st-team | 新增文件锁定服务、自定义角色服务、外部协作者管理、统计聚合接口 |
| 后端 | st-core | FileNode 实体新增锁定字段；文件操作前检查锁定状态 |
| 后端 | st-common | 定时任务清理过期外部协作者和过期锁 |
| 数据库 | docker/mysql/init | 23（file_node 锁定字段）、24（team_role 表）、25（team_member 外部字段+team_external_config） |
| 前端 | st-web | TeamSpacePage 新增锁定/解锁、角色管理弹窗、统计 Tab；成员弹窗新增外部标记 |

## 5. 风险

| 风险 | 等级 | 说明 | 缓解措施 |
|------|------|------|----------|
| 权限模型迁移 | 高 | role >= 100 需从 team_role 加载权限矩阵 | 预设角色 0/1/2 保留不变；checkPermission 先判断 role < 100 走原逻辑 |
| 锁定检查侵入性 | 中 | 所有文件操作需检查锁定状态 | 在 Controller 层统一拦截，不侵入 FileService |
| 外部协作者安全 | 中 | 外部人员访问组织文件 | member_type 标记 + 有效期 + 全局开关 |
| 统计查询性能 | 中 | 大量文件时聚合查询慢 | 限制统计范围在当前空间；走索引 |

## 6. 验收标准

### P2-1 文件锁定
- [ ] 编辑者可锁定文件/文件夹
- [ ] 锁定后其他人无法修改/删除/重命名/移动
- [ ] 锁定人可解锁
- [ ] 管理员可强制解锁
- [ ] 锁定 24h 后自动过期
- [ ] 文件列表显示锁定图标和锁定人
- [ ] 锁定/解锁记录到活动日志

### P2-2 自定义角色
- [ ] 管理员可创建自定义角色并勾选 9 项权限
- [ ] 角色可编辑/停用/启用
- [ ] 已使用角色不可删除
- [ ] 邀请成员时可选自定义角色
- [ ] 预设三级角色不受影响
- [ ] 自定义角色权限校验正确

### P2-3 外部协作者
- [ ] 管理员可将成员标记为外部协作者
- [ ] 外部协作者可设有效期
- [ ] 到期自动移除
- [ ] 管理员可开关外部协作
- [ ] 成员列表区分内外部

### P2-4 空间统计仪表板
- [ ] 设置弹窗有统计 Tab
- [ ] 展示存储用量概览
- [ ] 展示文件类型占比饼图
- [ ] 展示成员活跃度排行
- [ ] 展示近期操作统计柱状图
- [ ] 支持 7/30/90 天时间筛选
