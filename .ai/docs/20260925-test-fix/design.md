# 测试失败修复设计（定版）

目标与场景：云端删除本地文件时，用户并发编辑不能因复制旧版本后 unlink 丢失。默认 Maven 测试不得把开发库索引重建当作测试。

恢复流程：同一文件系统内将整个源文件/目录原子 rename 到恢复目录；禁止 copy/unlink 回退。应用数据目录与源在不同设备时，在同步根父目录的 `.st-cloud-sync-recovery` 保留原件。恢复目录必须在所有同步根之外，含实际路径检查。写 pending 清单、通知 watcher、执行一次 rename、写 complete 清单。目录无需逐文件删除，遍历之后新增内容亦随整目录移动。打开的文件句柄仍指向保留的原件；Windows 拒绝移动时源保持不变，事件失败重试。

异常与兼容：保留原 files/相对路径布局及清单字段。旧 pending 清单若目标已有内容，拒绝覆盖，保留双方供恢复；complete 事件重放不删除新出现的同名源文件。rename 成功但清单提交失败时原件仍留在恢复位置。EXDEV、权限错误、根目录为卷根且无安全恢复位置均安全失败，不退回复制删除。无 API 或数据库变化，ID 继续为字符串。

测试隔离：ReindexIntegrationTest 使用显式 Spring 测试上下文，真实 SearchServiceImpl 配合 mock Mapper/ES/Storage 边界；断言构造的索引请求和大 ID。它是服务编排集成测试，不声明覆盖完整应用启动或真实 Elasticsearch。

回归：复用 TC04-30 原探针；新增真实临时目录覆盖校验后编辑、目录遍历后新增、打开句柄后续写入、rename 失败、跨设备选址、已有目标不覆盖、重放不清理新文件、恢复位置与同步根重叠拒绝、清单提交失败后原件保留。执行桌面 npm test、tsc、主进程构建及 Maven test。

风险：同盘恢复目录由应用数据目录变为同步根旁目录时，用户应按日志返回的恢复路径查找；旧 pending 数据不会自动合并覆盖。没有待裁决的范围或兼容性问题。
