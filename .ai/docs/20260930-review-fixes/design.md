# 定版实施设计（review-fixes-design-v1）

目标与场景、边界、规则、API 与风险见 requirement.md、impact.md、uispec.md。当前定版决策如下。

1. 注册数据库步骤使用 READ COMMITTED 事务模板，锁后检查租户状态、角色状态及用户名，完成用户/角色写入后提交。独立签发阶段读取当前用户与权限，对版本及租户状态再次校验，签发成功后保存 refresh。外部调用不位于写事务内；事务回滚不会签发。
2. 邀请成员、成员角色变更、创建/接受邀请、创建/更新/删除角色统一限定 READ COMMITTED。空间锁后重做权限或邀请状态/空间状态判断；引用判断不受锁前快照影响。
3. FileService.getNodeDetail 所有权检查后，回收态及回收祖先返回 2008。禁止其他身份获取此状态；正常节点仍执行既有可访问检查。桌面仍仅接受 2001/2008 表示不可用，403/网络错误停止本页。
4. MOVE/RENAME 中只有补下载分支把 item 的 size/md5/updatedAt 换成刚读取的当前节点内容。源文件直接 rename 时使用旧映射基线，不把云端新内容冒充本地内容。源缺失而目标已有同节点成功映射时，删除同节点旧映射再退出。
5. startSync 先严格获取并应用 exclusions，再 engine.start。获取失败/全量失败抛错，停止资源并删除 engines 缓存，允许再次启动；未完整对账不能固化新版本。
6. 分享胶卷按包含分享来源和节点版本的缩略图 URL 记失败，失败分支与不支持格式分支呈现同一图片图标，名称和导航按钮不变。
7. 45 改成 INFORMATION_SCHEMA 判断后的条件 DDL，并新增递增编号同等修复脚本。H2 结构已一致，无需改变字段；记录校验事实。任务隔离 MySQL 运行迁移/版本登记，两次 compare-schema 退出 0 后才通过。

向后兼容：正常 API 不变，回收状态改用已有业务码；桌面升级安全失败后可重试。无全局隔离变更、无数据删除、无新业务表字段。无未决范围/风险决策。
