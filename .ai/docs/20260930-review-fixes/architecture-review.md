# 技术方案评审

采用现有安全写锁与空间写锁序列化相关决策。仅对这些事务采用 READ COMMITTED，并在锁后重读决策数据，避免锁前快照污染；不改全局隔离配置。

注册把数据库写入放入明确事务边界，返回已提交用户后读取会话快照；快照前后安全版本检查，任何并发撤权生成的旧版本令牌都无法通过主库校验。禁止在数据库写事务内写 Redis。

个人节点详情在所有权/租户校验后明确回收状态，使用已有 FILE_IN_RECYCLE，不把 403 解释为删除。

桌面保持整页成功后才确认游标，下载仍使用长度/哈希验证。普通本地移动与补下载分别保留其真实基线；失败启动清理实例，下一次重新全量对账。

迁移元数据判断使用 MySQL 支持的 PREPARE/EXECUTE，既有字段不做重复 ALTER，不改变其数据。UI 按 URL 记录失败并呈现现有通用图片图标。

方案范围明确，无待裁决事项。重点审查：注册提交边界、锁后角色/邀请重读、失权拒绝、移动重放及排除获取失败。
