# 需求评审：团队空间 P1 协作增强

> 本文档与 UI/UX 设计文档（uiSpec）同步产出，经需求评审多方会议（PM + UI + 前端 + 后端 + 测试）定版后，共同作为前端实现的唯一依据。
> 关联调研文档：`.ai/docs/20260809-teamspace-iteration-discovery.md`
> 关联 P0 文档：`.ai/docs/20260809-teamspace-p0/`

## 1. 背景

P0 迭代已补齐团队空间基础协作能力（邀请链接、空间设置、活动日志、退出/移交、活跃追踪），完成度从 10.8% 提升至约 35%。P1 聚焦"协作增强"，目标是让团队空间从"可用"达到"好用"水平（完成度约 60%）。

当前协作痛点：
- **权限粗粒度**：仅空间级三级角色，无法对特定文件夹设置不同权限（如财务文件夹仅查看、项目文件夹可编辑）
- **协作沟通割裂**：文件相关讨论散落在 IM 工具中，无法与文件关联
- **零通知**：成员被@提及、被邀请、文件变更等无任何提醒，需主动查看活动日志
- **空间管理低效**：多个空间时无法搜索/排序/置顶，找空间靠翻页

## 2. 用户故事

### P1-1 文件夹级权限
> 作为空间管理员，我希望能对特定文件夹设置不同的访问权限，例如让某成员只能查看"财务"文件夹但可编辑"项目"文件夹。

### P1-2 文件评论与@提及
> 作为空间成员，我希望能在文件上发表评论并@同事，让协作沟通与文件关联而非散落在聊天工具中。

### P1-3 站内通知体系
> 作为空间成员，当有人@我、邀请我加入空间、或我关注的文件发生变更时，我希望收到通知。

### P1-4 空间搜索与排序
> 作为用户，当我有多个团队空间时，我希望能搜索和排序以便快速找到目标空间。

## 3. 功能范围

### 3.1 P1-1 文件夹级权限

**功能点：**

1. 管理员可对空间内任意文件夹设置权限覆盖：
   - 权限级别：查看（2）/编辑（1）/管理（0）/无权限（-1）
   - 授权对象：指定成员（member）或指定角色（role）
2. 权限继承规则：
   - 子文件夹默认继承父文件夹权限
   - 可显式在子文件夹设置权限覆盖（中断继承）
   - 文件（非文件夹）始终继承其所在文件夹的权限
3. 权限校验链：
   - 查询文件/文件夹权限时，从当前节点向上遍历至空间根，取最近一条覆盖规则
   - 无覆盖规则时回退到空间级角色权限
4. 文件操作受文件夹权限约束：
   - 查看（listFiles/getNodeById）：需查看权限
   - 编辑（上传/创建文件夹/重命名/移动/删除）：需编辑权限
   - 管理（设置文件夹权限）：需管理权限
5. 前端文件浏览器根据权限控制操作按钮显隐
6. "无权限"文件夹对成员不可见（列表中不展示）

**数据模型：**

新增 `team_folder_permission` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 权限记录ID |
| tenant_id | BIGINT | 租户ID |
| space_id | BIGINT | 空间ID |
| folder_node_id | BIGINT | 文件夹节点ID |
| subject_type | VARCHAR(10) | 授权对象类型：role/member |
| subject_id | BIGINT | 角色值或用户ID |
| permission | TINYINT | 权限：-1-无权限 0-管理 1-编辑 2-查看 |
| created_at / updated_at / deleted | - | 基础字段 |
| 索引 | | IDX(folder_node_id, subject_type, subject_id) |

### 3.2 P1-2 文件评论与@提及

**功能点：**

1. 文件详情/预览侧边栏支持发表评论
2. 评论内容支持 @提及空间内成员（输入 `@` 触发成员选择）
3. 被@提及的成员收到站内通知（依赖 P1-3 通知体系）
4. 评论支持回复（二级嵌套，parent_id 关联）
5. 评论可编辑（本人）、可删除（本人或管理员）
6. 评论列表分页加载（每页 20 条，按时间正序）
7. 评论显示：头像、昵称、内容、时间、回复按钮

**数据模型：**

新增 `team_comment` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 评论ID |
| tenant_id | BIGINT | 租户ID |
| space_id | BIGINT | 空间ID |
| node_id | BIGINT | 文件节点ID |
| user_id | BIGINT | 评论人ID |
| content | TEXT | 评论内容 |
| parent_id | BIGINT | 父评论ID（NULL=顶级评论） |
| mentions | VARCHAR(500) | @提及的用户ID列表（逗号分隔） |
| created_at / updated_at / deleted | - | 基础字段 |
| 索引 | | IDX(node_id, created_at) |

### 3.3 P1-3 站内通知体系

**功能点：**

1. 新增站内通知中心：
   - 顶部导航栏铃铛图标，显示未读数
   - 点击展开通知列表（最近 20 条）
   - 全部通知页面（分页）
2. 通知类型：
   - `MENTION`：评论中被@提及
   - `TEAM_INVITE`：被邀请加入空间
   - `FILE_CHANGE`：关注文件被修改/删除（P1 简化为评论通知，文件变更通知预留）
   - `MEMBER_CHANGE`：成员变动（被移除等）
3. 通知内容：标题、正文、关联类型（team/comment/file）、关联ID、时间
4. 通知状态：已读/未读，支持单条已读、批量已读、全部已读
5. 点击通知跳转到关联页面（如评论通知跳转文件详情）
6. 预留邮件/WebHook 扩展点（P1 不实现）

**数据模型：**

新增 `notification` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 通知ID |
| tenant_id | BIGINT | 租户ID |
| user_id | BIGINT | 接收者ID |
| type | VARCHAR(20) | 通知类型：MENTION/TEAM_INVITE/FILE_CHANGE/MEMBER_CHANGE |
| title | VARCHAR(200) | 通知标题 |
| content | VARCHAR(500) | 通知正文 |
| ref_type | VARCHAR(20) | 关联类型：team/comment/file |
| ref_id | BIGINT | 关联ID |
| read | TINYINT | 0-未读 1-已读 |
| created_at | - | 基础字段 |
| 索引 | | IDX(user_id, read, created_at) |

### 3.4 P1-4 空间搜索与排序

**功能点：**

1. 空间列表页新增搜索框，按空间名称模糊搜索
2. 支持排序：创建时间（默认）、成员数、存储用量，可切换升降序
3. 支持置顶/收藏常用空间：
   - 置顶空间显示在列表最前
   - 点击空间卡片上的图钉图标切换置顶状态
4. 置顶状态持久化到 `team_member.is_pinned`

**数据模型：**

`team_member` 表新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| is_pinned | TINYINT | 是否置顶：0-否 1-是，默认0 |

## 5. 风险

| 风险 | 等级 | 说明 | 缓解措施 |
|------|------|------|----------|
| 文件夹权限校验性能 | 高 | 每次文件操作需递归向上遍历权限链 | 权限链计算结果缓存；限制权限覆盖层级深度 |
| checkPermission 重构侵入性 | 高 | 改动核心权限校验签名，影响所有团队文件操作 | 保留旧签名兼容；新增重载方法；充分测试回归 |
| 通知实时性 | 中 | 站内通知需及时推送 | P1 用轮询（30s）拉取未读数，后续可升级 WebSocket |
| @提及解析复杂度 | 中 | 评论内容中解析@用户名 | 前端选择成员后插入标记，后端直接解析 mentions 字段 |
| 权限继承中断边界 | 中 | 子文件夹中断继承后父权限不再生效 | 明确"最近覆盖规则"语义，UI 明确提示继承状态 |
