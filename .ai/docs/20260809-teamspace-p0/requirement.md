# 需求评审：团队空间 P0 基础协作补齐

> 本文档与 UI/UX 设计文档（uiSpec）同步产出，经需求评审多方会议（PM + UI + 前端 + 后端 + 测试）定版后，共同作为前端实现的唯一依据。
> 关联调研文档：`.ai/docs/20260809-teamspace-iteration-discovery.md`

## 1. 背景

星云盘团队空间功能完成度仅 10.8%（37 项功能仅 4 项已有），协作能力完全空白。当前核心痛点：

- **邀请低效**：仅支持按用户名直接添加，无邀请链接，无法批量或异步邀请
- **设置残缺**：空间设置弹窗仅能调整存储配额，名称/描述/图标无法编辑（后端 `PUT /api/team/{spaceId}` 已支持字段更新，前端表单缺失）
- **零协作感知**：无空间活动日志，成员无法了解空间内发生了什么操作
- **生命周期断裂**：成员无法主动退出空间，拥有者无法移交所有权，`last_active_at` 字段存在但从未更新

P0 迭代目标：补齐基础协作能力，让团队空间从"勉强可用"达到"可用"基线，完成度提升至约 35%。

## 2. 用户故事

### P0-1 邀请链接机制
> 作为空间管理员，我希望生成邀请链接分享给同事，他们点击即可加入空间，而无需逐个输入用户名。

### P0-2 空间设置完善
> 作为空间管理员，我希望能编辑空间名称、描述和图标，而不仅仅是调整存储配额。

### P0-3 空间活动日志
> 作为空间成员，我希望看到空间内最近发生了什么操作（谁上传/删除/邀请了谁），以便了解团队动态。

### P0-4 成员退出与所有权移交
> 作为普通成员，我希望可以主动退出不需要的空间；作为空间拥有者，我希望可以将空间移交给他人后安心离开。

### P0-5 成员活跃追踪
> 作为管理员，我希望看到成员最后活跃时间，以识别不活跃成员进行清理。

## 3. 功能范围

### 3.1 P0-1 邀请链接机制

**功能点：**

1. 管理员可生成空间邀请链接，包含以下可配置项：
   - 默认角色（查看者/编辑者/管理员）
   - 有效期（24小时 / 7天 / 永久）
2. 邀请链接生成后返回完整 URL（`/team/invite/{code}`）
3. 被邀请人点击链接后的加入流程：
   - 未登录 -> 跳转登录页，登录后自动跳回邀请页
   - 已登录且非成员 -> 直接加入空间（P0 不做审批流，直接加入）
   - 已登录且已是成员 -> 提示"您已是该空间成员"并跳转空间
4. 邀请链接管理：
   - 查看已生成的邀请链接列表（含创建时间、角色、有效期、使用状态）
   - 撤销（失效）邀请链接
5. 邀请链接使用后不自动失效（一个链接可多人使用，直到过期或被撤销）

**数据模型：**

新增 `team_invite` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 邀请记录ID |
| tenant_id | BIGINT | 租户ID |
| space_id | BIGINT | 空间ID |
| invite_code | VARCHAR(32) | 邀请码（唯一，URL 友好） |
| role | TINYINT | 默认角色：0-管理员 1-编辑者 2-查看者 |
| created_by | BIGINT | 创建者ID |
| expire_at | DATETIME | 过期时间，NULL=永久 |
| status | TINYINT | 0-已撤销 1-有效 |
| created_at / updated_at | - | 基础字段 |
| 索引 | | UK(invite_code), IDX(space_id, status) |

### 3.2 P0-2 空间设置完善

**功能点：**

1. 空间设置弹窗扩展为完整表单：
   - 空间名称（必填，最长 100 字符）
   - 空间描述（选填，最长 500 字符）
   - 空间图标（emoji 选择器，预设常用 emoji 列表）
   - 存储配额（保留现有逻辑）
2. 保存后列表页与详情页同步更新
3. 复用现有 `PUT /api/team/{spaceId}` 接口（后端已支持字段级更新，前端补全表单即可）

**数据模型：** 无变更（`team_space` 表已有 `space_name`/`description`/`icon` 字段）

### 3.3 P0-3 空间活动日志

**功能点：**

1. 空间详情页新增"动态"Tab，展示空间内操作时间线
2. 记录的操作类型：
   - 文件操作：上传、删除、重命名、移动、复制、创建文件夹
   - 成员操作：加入、退出、角色变更、移除
   - 空间操作：设置修改、邀请链接创建/撤销
3. 每条记录包含：操作人（头像+昵称）、操作类型、目标对象名称、时间戳
4. 支持按操作类型筛选（全部/文件/成员/空间）
5. 分页加载（每页 20 条，按时间倒序）
6. 活动日志仅空间成员可见（查看者可读）
7. 活动日志保留 90 天，定时清理过期记录

**数据模型：**

新增 `team_activity` 表（空间级活动流，区别于全局 `audit_log`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 活动ID |
| tenant_id | BIGINT | 租户ID |
| space_id | BIGINT | 空间ID |
| user_id | BIGINT | 操作人ID |
| username | VARCHAR(100) | 操作人用户名（冗余，便于展示） |
| nickname | VARCHAR(100) | 操作人昵称（冗余） |
| action | VARCHAR(50) | 操作类型：FILE_UPLOAD/FILE_DELETE/MEMBER_JOIN 等 |
| target_type | VARCHAR(30) | 目标类型：FILE/FOLDER/MEMBER/SPACE |
| target_id | BIGINT | 目标ID |
| target_name | VARCHAR(255) | 目标名称 |
| detail | TEXT | 操作详情(JSON) |
| created_at | - | 基础字段 |
| 索引 | | IDX(space_id, created_at) |

> 选择新建 `team_activity` 而非扩展 `audit_log`：审计日志是全局安全合规视角（含 IP/UA），空间活动流是成员协作视角（含用户展示信息），关注点与访问范围不同。

### 3.4 P0-4 成员退出与所有权移交

**功能点：**

1. 成员主动退出空间：
   - `POST /api/team/{spaceId}/leave`
   - 非管理员可直接退出
   - 管理员退出前校验：若该管理员是空间拥有者，须先移交所有权；若退出后空间无管理员，须先提升其他成员为管理员
   - 最后一名成员退出时阻止并提示"空间至少保留一名成员"
2. 所有权移交：
   - `POST /api/team/{spaceId}/transfer`（参数：targetMemberId）
   - 仅空间拥有者可操作
   - 目标必须是当前空间的管理员（role=0）
   - 移交后：原拥有者降为管理员（role=0），目标成员不变（已是管理员），`team_space.owner_id` 更新为目标用户
   - 移交记录写入活动日志
3. 退出空间后文件归属不变（文件属于空间而非个人），退出成员失去访问权
4. 前端成员管理弹窗：
   - 非拥有者展示"退出空间"按钮
   - 拥有者展示"移交所有权"入口，退出时引导先移交

### 3.5 P0-5 成员活跃追踪

**功能点：**

1. 成员访问空间时更新 `last_active_at`：
   - 触发点：浏览空间文件列表（`GET /{spaceId}/files`）、空间详情（`GET /{spaceId}`）
   - 更新频率限制：同一用户 5 分钟内不重复更新（避免高频写入）
2. 成员列表展示最后活跃时间（已有 `lastActiveAt` 字段，前端展示）
3. 成员列表支持按活跃时间排序
4. 展示活跃状态标签：1小时内活跃（绿）、1天内活跃（黄）、7天内活跃（灰）、超7天（灰暗）

**数据模型：** 无变更（`team_member.last_active_at` 字段已存在，代码需补充更新逻辑）

## 5. 风险

| 风险 | 等级 | 说明 | 缓解措施 |
|------|------|------|----------|
| 邀请链接安全 | 高 | 邀请链接可被转发，非预期人员加入 | 邀请码使用加密随机串（32位）；管理员可随时撤销；记录邀请加入的活动日志 |
| 活动日志写入量 | 中 | 高频文件操作产生大量活动记录 | 异步写入（复用审计日志的线程池模式）；90天定时清理；分页查询走索引 |
| 活跃追踪写入频率 | 中 | 每次访问空间都更新可能产生高频写入 | 5分钟内同一用户不重复更新；仅更新时间戳字段 |
| 所有权移交一致性 | 高 | 移交涉及 owner_id 与角色双重更新 | 事务保证原子性；移交前校验目标必须是管理员 |
| 退出空间数据完整性 | 中 | 成员退出后其上传文件归属 | 文件归属空间而非个人（现有设计已满足），退出仅删 team_member 记录 |
| 前端表单复用 | 低 | 设置弹窗需重构现有仅配额的表单 | 后端接口已支持，纯前端改造 |

## 6. 验收标准

### P0-1 邀请链接机制
- [ ] 管理员可在成员管理弹窗生成邀请链接，选择角色和有效期
- [ ] 邀请链接 URL 格式为 `/team/invite/{code}`，code 为 32 位随机串
- [ ] 未登录用户点击链接 -> 跳转登录 -> 登录后自动加入空间并跳转空间页
- [ ] 已登录非成员用户点击链接 -> 直接加入空间并跳转
- [ ] 已是成员用户点击链接 -> 提示已是成员并跳转空间
- [ ] 管理员可查看邀请链接列表（创建时间、角色、有效期、状态）
- [ ] 管理员可撤销邀请链接，撤销后链接不可用
- [ ] 过期邀请链接点击后提示"链接已过期"

### P0-2 空间设置完善
- [ ] 设置弹窗包含名称、描述、图标、配额四个字段
- [ ] 图标支持从预设 emoji 列表选择
- [ ] 保存后空间列表页和详情页同步显示新名称/描述/图标
- [ ] 名称为空时校验提示

### P0-3 空间活动日志
- [ ] 空间详情页有"动态"Tab，展示活动时间线
- [ ] 文件上传/删除/重命名/移动/复制/创建文件夹均有活动记录
- [ ] 成员加入/退出/角色变更/移除均有活动记录
- [ ] 空间设置修改有活动记录
- [ ] 邀请链接创建/撤销有活动记录
- [ ] 活动记录含操作人头像、昵称、操作类型、目标名称、时间
- [ ] 支持按操作类型筛选（全部/文件/成员/空间）
- [ ] 查看者可查看活动日志

### P0-4 成员退出与所有权移交
- [ ] 非管理员成员可主动退出空间
- [ ] 管理员退出时若为拥有者，提示先移交所有权
- [ ] 管理员退出时若无其他管理员，提示先提升成员
- [ ] 最后一名成员退出被阻止
- [ ] 拥有者可将所有权移交给另一名管理员
- [ ] 移交后原拥有者降为管理员，新拥有者 owner_id 更新
- [ ] 退出后失去空间访问权，文件归属不变
- [ ] 退出和移交操作记录到活动日志

### P0-5 成员活跃追踪
- [ ] 成员访问空间文件列表时 last_active_at 更新
- [ ] 同一用户 5 分钟内不重复更新
- [ ] 成员列表展示最后活跃时间
- [ ] 成员列表支持按活跃时间排序
- [ ] 活跃状态标签正确显示（1小时/1天/7天/超7天）
