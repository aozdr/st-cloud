# 星云盘 日志管理模块设计文档

> 版本: v1.0 | 日期: 2026-08-02 | 状态: 实施中

## 1. 背景与问题

### 1.1 现状

星云盘 有两类日志面向用户：

| 日志类型 | 位置 | 技术实现 | 现状 |
|---------|------|---------|------|
| 同步日志 | 桌面端 SyncPage | sync-engine.ts 通过 IPC 事件推送 | 已有白底卡片 UI，但混杂大量技术信息 |
| 审计日志 | Web AdminPage 审计 tab | AuditAspect 切面 + AuditLog 表 | 表格展示，无筛选，显示英文 action 代码 |

### 1.2 核心问题

1. **同步日志泄露技术细节**：日志中出现游标值（cursor）、变更条数、扫描状态等内部状态，用户无需也不应看到这些
2. **审计日志不可读**：操作列显示 UPLOAD/SYNC_ROOT_CREATE 等英文代码而非中文；detail 字段曾是 JSON 格式
3. **审计日志无筛选**：后端支持按用户名/操作类型/状态筛选，但前端未提供筛选控件
4. **缺乏信息分层**：所有日志一视同仁，无类型过滤、无重要性区分

### 1.3 用户痛点

- **个人用户**：只关心「我同步了哪些文件」，不想看到「游标 12345」「拉取云端变更 5 项」
- **管理员**：想快速定位「谁在什么时间做了什么」，需要按操作类型和用户筛选，而非翻页查找

## 2. 目标

| 目标 | 衡量标准 |
|------|---------|
| 同步日志只显示用户可理解的文件操作 | 日志中不出现 cursor/nodeId/变更条数等内部 ID |
| 审计日志全中文、可筛选 | 操作列显示中文标签；提供操作类型+用户名+状态三重筛选 |
| 日志按类型可过滤 | 同步日志支持按类型 tab 过滤；审计日志支持操作类型下拉 |
| 信息密度合理 | 每条日志一行可读，关键信息一眼可见 |

## 3. 用户场景

### 场景一：查看同步状态（个人用户）
> 小李打开同步页面，想确认刚才拖入同步文件夹的照片是否已上传。
> 他看到日志列表：「上传新文件: DSC_0123.jpg」「上传完成: DSC_0123.jpg」，不需要理解游标或变更计数。

### 场景二：审计排查（管理员）
> 老张发现一个团队文件夹里少了文件，打开管理后台审计日志。
> 他在筛选栏选「操作类型: 删除」，输入用户名「王经理」，立即看到相关操作记录，detail 列显示「删除 2 个文件至回收站」。

## 4. 设计方案

### 4.1 同步日志（SyncPage）

#### 4.1.1 日志信息规范

**应记录（用户可理解的操作）：**

| 类型 | 示例消息 |
|------|---------|
| 上传 | 上传新文件: report.docx |
| 更新 | 更新文件: notes.txt |
| 下载 | 下载文件: design.png |
| 删除 | 删除文件: draft.txt（云端已删除） |
| 创建 | 创建文件夹: 项目资料 |
| 冲突 | 文件冲突: budget.xlsx（已保留两份副本） |
| 信息 | 同步已启动 / 同步已停止 |
| 错误 | 同步失败: 网络连接超时 |

**不应记录（内部技术状态）：**
- ~~开始同步 · 游标 12345~~（游标是内部状态）
- ~~拉取云端变更 5 项~~（变更条数是技术细节）
- ~~扫描本地变更~~（扫描过程是内部步骤）

#### 4.1.2 UI 设计

- **类型过滤 tab**：全部 / 上传 / 下载 / 删除 / 冲突 — 点击后只显示对应类型日志
- **日志条目**：图标 + 类型标签 + 消息文本 + 时间，单行布局
- **移除 detail 字段**：不再显示技术详情（仅错误日志的消息中已包含原因）
- **清空按钮**：保留

### 4.2 审计日志（AdminPage）

#### 4.2.1 信息规范

- 操作列：中文标签（创建文件夹/移动/删除/上传/下载…），按类别配色
- 详情列：人类可读描述（如「删除 2 个文件至回收站」「创建文件夹「项目资料」」）
- 不显示 targetId（内部 ID，用户无关）

#### 4.2.2 操作标签配色

| 类别 | 操作 | 颜色 |
|------|------|------|
| 文件 | 上传/下载/创建/重命名/移动/复制 | 蓝色 |
| 删除 | 删除/永久删除/清空回收站/中止上传 | 红色 |
| 分享 | 创建/更新/取消/访问分享 | 琥珀色 |
| 团队 | 创建/更新/删除团队/邀请/移除成员 | 紫色 |
| 认证 | 注册/登录/退出/2FA | 绿色 |
| 同步 | 注册/注销/暂停同步 | 青色 |
| 系统 | 重建索引 | 石灰色 |

#### 4.2.3 UI 设计

- **筛选栏**：操作类型下拉（全部分组显示）+ 用户名搜索框 + 状态切换（全部/成功/失败）
- **表格列**：时间 / 用户 / 操作（彩色标签）/ 详情 / IP / 状态
- **时间格式**：保持 yyyy-MM-dd HH:mm:ss

## 5. 技术实现要点

### 5.1 同步日志
- sync-engine.ts：移除游标/变更条数/扫描日志，保留文件操作日志
- SyncPage.tsx：新增类型过滤 tab，移除 detail 字段渲染
- SyncLogEntry：detail 字段保留但前端不常规渲染（错误信息已在 message 中）

### 5.2 审计日志
- AdminPage.tsx：
  - 新增筛选状态（actionFilter, usernameFilter, statusFilter）
  - etchAuditLogs 传入选筛参数（后端已支持）
  - 操作标签配色按类别映射
  - 移除 targetId 显示，detail 列为主要信息

## 6. 验收标准

- [ ] 同步日志中不出现 cursor/nodeId/变更条数等技术信息
- [ ] 同步日志支持按类型 tab 过滤
- [ ] 审计日志操作列全中文、按类别配色
- [ ] 审计日志支持按操作类型+用户名+状态筛选
- [ ] 审计日志详情列显示人类可读描述
- [ ] 两端构建通过
