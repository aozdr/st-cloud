## 1. 执行摘要（Executive Summary）

我们正在构建 **星云盘**——一个完全免费、可私有化部署的云盘系统，同时服务个人用户与企业团队。系统支持 SaaS 多租户公有云与私有云单租户两种部署模式，首期覆盖 Web 端与 PC 桌面客户端，所有功能完全免费、无付费墙。

星云盘 旨在填补"商业网盘限速付费"与"自建网盘体验粗糙"之间的市场空白：对标百度网盘/阿里云盘的产品体验品质，同时保留 Nextcloud/ownCloud 的自建灵活性与数据主权。个人用户可获得不限速的大容量文件存储、影音在线播放与便捷分享；企业团队可获得团队空间、成员权限管理与本地文件同步，且数据可完全自托管。

**预期影响**：为个人用户提供零门槛的优质云存储体验，为企业团队提供数据自主可控、无隐性成本的文件协作平台。

## 2. 问题陈述（Problem Statement）

### 2.1 谁有这个问题？

- **个人用户**：有大量文件（照片、视频、文档、学习资料）需要存储和分享的普通用户，尤其是对商业网盘限速和付费墙不满的用户。
- **企业团队**：中小型企业和团队，需要一个安全可控的文件协作平台，但受限于预算无法采购昂贵的企业网盘服务。
- **IT 管理员 / 技术爱好者**：希望将数据完全掌握在自己手中的技术人员，需要一套可私有化部署、功能完整且体验优良的云盘系统。

### 2.2 问题是什么？

当前市场存在两极分化：

| 维度 | 商业网盘（百度网盘/阿里云盘等） | 自建网盘（Nextcloud/ownCloud 等） |
|------|------|------|
| 传输速度 | 非会员严重限速（常低于 100KB/s） | 速度不受限，但受服务器带宽制约 |
| 费用 | 免费功能受限，核心功能需付费（¥8-30/月） | 软件免费，但部署运维门槛高 |
| 用户体验 | 体验成熟，功能丰富 | 界面粗糙，交互体验差 |
| 数据主权 | 数据存储在第三方服务器，隐私不可控 | 数据自主可控，但需要技术能力维护 |
| 团队协作 | 企业版价格昂贵 | 协作功能基础，权限管理不完善 |

**核心矛盾**：用户既想要商业网盘的优质体验，又想要自建网盘的数据主权和零成本，但市场上缺少兼顾两者的产品。

### 2.3 为什么痛苦？

- **用户侧**：商业网盘限速导致下载一个 1GB 文件可能需要 30 分钟以上；免费空间不断缩水；分享链接频繁失效；隐私数据存在第三方服务器存在泄露风险。
- **企业侧**：企业网盘年费动辄数万元；数据存储在第三方存在合规风险（特别是金融、医疗、政务等敏感行业）；现有自建方案体验差导致员工抵触使用。
- **技术侧**：Nextcloud 等开源方案虽然免费可自建，但部署复杂、界面过时、性能一般、缺乏专业的 PC 桌面同步客户端，技术门槛将大量非专业用户挡在门外。

### 2.4 证据

- **行业数据**：百度网盘个人用户超 8 亿，但非会员限速问题长期被用户诟病，"百度网盘限速"相关搜索结果超千万条。
- **市场趋势**：阿里云盘以"不限速"为卖点快速崛起，证明用户对"免费 + 不限速"有强烈需求，但其商业化趋势（压缩包分享限制、空间缩水）正在重现百度网盘的老路。
- **开源生态**：Nextcloud GitHub Star 数超 22k，ownCloud 超 8k，表明大量用户有自建需求，但 issue 中普遍反映体验和性能问题。
- **企业需求**：数据安全法规（如《数据安全法》《个人信息保护法》）推动企业将数据存储回归自主可控，私有化部署需求持续增长。

### 4.2 市场机会

- **个人云存储市场**：全球云存储市场规模预计 2027 年超 2000 亿美元，年复合增长率约 24%。国内个人网盘用户超 7 亿，但满意度低（限速、付费墙、隐私担忧），存在大量寻求替代方案的用户。
- **企业文件协作市场**：中国中小企业超 4000 万家，其中大量企业无力承担企业网盘年费（通常 2-10 万元），对免费可自建的文件协作平台有强烈需求。
- **数据合规驱动**：《数据安全法》《个人信息保护法》等法规推动企业和机构将数据存储回归自主可控，私有化部署需求持续增长。
- **开源生态成熟**：云原生技术（Docker/K8s）、对象存储（MinIO/S3）、分布式文件系统等技术成熟，降低了构建高质量云盘的技术门槛。

### 4.3 Why Now？

1. **用户不满到达临界点**：商业网盘限速和付费墙问题持续恶化，阿里云盘也开始商业化，用户对免费不限速替代方案的需求达到历史高位。
2. **合规压力加剧**：数据安全法规趋严，企业和机构对数据自主可控的刚需从"可选"变为"必选"。
3. **技术条件成熟**：前端技术（React/Vue）、文件分片上传、WebRTC、桌面端技术（Electron/Tauri）的成熟，使构建体验比肩商业网盘的自建方案成为可能。
4. **竞品留有空白**：Nextcloud 体验粗糙且臃肿、Seafile 功能单一、商业网盘不支持私有化——市场缺少"体验好 + 可自建 + 完全免费"的产品。

## 5. 方案概述（Solution Overview）

### 5.1 产品架构

星云盘 采用 **双部署模式架构**，同一套代码支持两种部署形态：

```
┌─────────────────────────────────────────────────────┐
│                   客户端层                            │
│  ┌──────────────┐  ┌───────────────────────────┐    │
│  │  Web 端       │  │  PC 桌面客户端              │    │
│  │  (浏览器访问)  │  │  (Windows/macOS)          │    │
│  │  文件管理/预览 │  │  本地同步/虚拟磁盘/右键菜单  │    │
│  └──────────────┘  └───────────────────────────┘    │
└──────────────────────┬──────────────────────────────┘
                       │ HTTPS REST API
┌──────────────────────┴──────────────────────────────┐
│                   服务端层                            │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ │
│  │ 用户服务  │ │ 文件服务  │ │ 分享服务  │ │ 搜索   │ │
│  │ 认证/权限 │ │ 上传/下载 │ │ 链接/提取码│ │ 索引   │ │
│  └──────────┘ └──────────┘ └──────────┘ └────────┘ │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ │
│  │ 团队服务  │ │ 同步服务  │ │ 预览服务  │ │ 审计   │ │
│  │ 空间/成员 │ │ 增量/冲突 │ │ 文档/影音 │ │ 日志   │ │
│  └──────────┘ └──────────┘ └──────────┘ └────────┘ │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────┴──────────────────────────────┐
│                   存储层                              │
│  ┌────────────────────────────────────────────┐     │
│  │  对象存储（本地磁盘 / MinIO / S3 兼容）       │     │
│  └────────────────────────────────────────────┘     │
│  ┌────────────────┐  ┌────────────────────────┐     │
│  │  元数据存储      │  │  搜索索引（Elasticsearch）│     │
│  │  (MySQL/PG)     │  │                        │     │
│  └────────────────┘  └────────────────────────┘     │
└─────────────────────────────────────────────────────┘
```

**部署模式说明**：

| 部署模式 | 适用场景 | 多租户 | 数据存储 | 典型用户 |
|------|------|------|------|------|
| **SaaS 公有云** | 个人用户注册即用 | ✅ 多租户隔离 | 云端对象存储 | 个人用户、小团队 |
| **私有云自建** | 企业/机构内网部署 | ⚠️ 单租户为主 | 本地磁盘/私有对象存储 | 企业、IT 管理员 |

| **体验对标商业网盘** | 界面现代化、交互流畅、功能完整 | vs Nextcloud/ownCloud 界面过时体验差 |
| **数据自主可控** | 私有化部署数据不出内网 | vs 商业网盘数据存储在第三方 |
| **专业桌面同步客户端** | 原生 PC 客户端，支持虚拟磁盘和右键菜单 | vs Nextcloud 客户端性能差；Seafile 客户端功能少 |

### 5.4 用户流程（核心路径）

**流程一：个人用户上传与分享文件**
```
登录 -> 进入文件管理页面 -> 拖拽/选择文件上传 -> 上传进度显示（分片/断点续传）
-> 上传完成 -> 右键文件选择分享 -> 设置权限/密码/有效期 -> 生成分享链接 -> 复制链接分享给他人
```

**流程二：企业团队协作**
```
管理员创建团队空间 -> 邀请成员并分配角色（管理员/编辑者/查看者）
-> 成员在团队空间上传/管理文件 -> 共享文件夹多人协作 -> 操作审计日志记录
```

**流程三：PC 客户端文件同步**
```
安装 PC 客户端 -> 登录账号 -> 选择同步文件夹 -> 客户端自动监听本地变更
-> 增量上传至云端 -> 云端变更自动同步到本地 -> 冲突时生成冲突副本
```

## 7. 用户故事与需求（User Stories & Requirements）

### 7.1 Epic Hypothesis

> 我们相信，为个人用户和企业团队构建一个完全免费、可私有化部署、体验对标商业网盘的云盘系统，将吸引对商业网盘限速付费不满的个人用户和寻求数据自主可控的企业团队，因为我们解决了"体验好"与"数据可控"无法兼得的市场空白。我们将通过月活跃用户数和团队空间创建数来衡量成功。

### 7.10 约束与边界情况

| 约束类型 | 说明 |
|------|------|

| **分享限制** | 单个用户最大活跃分享链接 1000 个 |

| **存储空间不足** | 上传前检查配额，不足时拒绝上传并提示 |
| **权限继承** | 子文件夹默认继承父文件夹权限，可显式覆盖 |

## 8. 范围外（Out of Scope）

以下功能明确不在首期范围内，避免范围蔓延：

| 排除项 | 排除理由 |
|------|------|
| **移动端 App（iOS/Android）** | 首期聚焦 Web + PC 桌面端，移动端需独立开发资源，放到二期规划 |
| **在线文档协同编辑** | 协同编辑技术复杂度高（OT/CRDT），首期仅支持文档预览，编辑需下载后本地编辑再上传 |
| **AI 智能功能** | AI 搜索、智能分类、人脸识别等功能依赖大量训练数据和算力，首期不包含 |
| **支付/会员系统** | 产品定位完全免费，无需支付系统 |
| **日历/联系人/邮件等 PIM 功能** | 聚焦文件存储与协作核心能力，不做全功能 Groupware（与 Nextcloud 区分） |
| **第三方应用生态/插件市场** | 首期聚焦核心功能完善，插件生态放到远期规划 |
| **端到端加密（E2EE）** | 技术复杂度高且影响预览/搜索等功能，首期仅支持传输加密+存储加密 |
| **区块链/去中心化存储** | 与产品定位不符，不纳入 |
| **FTP/WebDAV 协议支持** | 首期使用自有 API，兼容协议放到二期 |

### 9.2 风险与缓解措施

#### 风险一：用户价值风险（Cagan 四类风险之一）
**风险**：用户可能不愿意从已有的商业网盘迁移到新平台，迁移成本高。

**缓解措施**：
- 提供文件批量导入工具（从百度网盘/本地批量迁移）
- SaaS 模式零注册门槛，降低尝试成本
- 私有化部署吸引有刚需的企业用户作为种子用户
- 对标商业网盘体验，确保迁移后体验不降级

#### 风险二：可用性风险（Cagan 四类风险之二）
**风险**：大文件上传/下载的稳定性和速度可能无法达到商业网盘水平。

**缓解措施**：
- 采用分片上传 + 断点续传确保大文件可靠性
- 使用 CDN 加速下载（SaaS 模式）
- 性能基准测试：确保上传速度达到带宽 80%+
- 限流与排队机制防止资源耗尽

#### 风险三：可行性风险（Cagan 四类风险之三）
**风险**：PC 桌面同步客户端开发复杂度高，跨平台兼容性问题多。

**缓解措施**：
- 使用 Electron/Tauri 框架降低跨平台开发难度
- 同步引擎采用成熟的增量同步算法
- 优先支持 Windows，macOS 作为紧随其后的目标
- 充分的冲突处理测试（模拟并发修改场景）

#### 风险四：商业可行性风险（Cagan 四类风险之四）
**风险**：完全免费模式下 SaaS 运营成本（带宽、存储）可能不可持续。

**缓解措施**：
- SaaS 模式设置合理配额（10GB/用户），控制成本
- 私有化部署用户自行承担存储成本，不增加平台负担
- 开源社区贡献降低开发成本
- 远期可引入可选的增值服务（如额外存储空间购买）作为可持续性补充

#### 风险五：安全风险
**风险**：多租户数据隔离不当导致跨租户数据泄露。

**缓解措施**：
- 所有数据查询强制附加租户 ID 过滤
- 安全测试包含跨租户访问测试用例
- 定期进行安全审计和渗透测试
- 审计日志记录所有文件访问行为
